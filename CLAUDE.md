# Space Station Recipes — правила проекта

Глобальные правила (язык, git, документы, task management, tiers) — в `~/.claude/CLAUDE.md`. Здесь только то, что специфично для этого репозитория.

## Стратегические документы

- **Vision:** [VISION.md](VISION.md) — верх иерархии Vision > ROADMAP > задачи. Каждая серия ROADMAP ссылается на ставку из VISION §6; серия без ставки не стартует. Vision меняется только вместе с записью в `docs/decisions/`.
- **Roadmap/workbook:** [ROADMAP.md](ROADMAP.md) — серии и инкременты с HAE, Definition of Done в §0 (e2e-проверка в превью, cache-bust `?v=N` + `PRECACHE` + `CACHE` в `sw.js`, коммит после верификации, аудит каждые 4 инкремента).
- **Качество:** [AUDIT.md](AUDIT.md) (baseline 2026-09-11, план исправлений = серия Q). Записи решений — `docs/decisions/YYYY-MM-DD_topic.md`, спеки — `docs/design/`, планы — `docs/superpowers/plans/`, исследования — `research/`.

## Среда (Windows 10, PowerShell + Git Bash)

- Превью: `.claude/launch.json`, конфигурация `ss14-chem` (python `http.server`, bind `127.0.0.1` обязателен — иначе `localhost` уходит в IPv6 и отказывает).
- Python `subprocess(['bash'])` попадает в WSL-лаунчер из System32; передавать путь Git Bash (`cygpath -w "$(which bash)"`).
- Heredoc длиннее ~100 строк в Bash-инструменте не парсится — скрипты писать в scratchpad и запускать файлом.
- Консольная кодовая страница ломает вывод с кириллицей и тире: для Python ставить `PYTHONIOENCODING=utf-8`.

## Параллельные сессии

- Над репозиторием одновременно работают 2–3 сессии. Перед правкой общих файлов (`ROADMAP.md`, `app.js`, `index.html`, `sw.js`, `sections.json`) — `git status` и проверка mtime; коммитить только свои файлы; при чужих правках в том же файле стейджить только свои ханки.
- Скрипты, которые выглядят read-only, но пишут отслеживаемые файлы: `--selfcheck` экстрактора карт перепекает `maps/vanilla/Bagel.*`, `--verify` сборщика ordnance перезаписывает JSON и спрайты. В корне репозитория во время аудитов не запускать.

## Аналитика и внешние сервисы

- Экспорт Яндекс.Метрики (`scripts/export_metrika_*.py`, токен из `.env`) — только после явного «ок» владельца в той же сессии.
- Push в origin и регистрация целей Метрики — только по явному запросу владельца.
- Функции, которым нужна санкция администрации сервера (командный планшет и любые общие «комнаты»), не пилотируются на живых серверах без письменного «да»; см. VISION §4 п.3.
