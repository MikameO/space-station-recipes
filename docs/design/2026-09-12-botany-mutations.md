## Проблема

На вкладке Botany есть три вещи: сетка химикатов с растительными эффектами,
дерево эволюции видов и курируемый блок `BOTANY_GUIDE`. Чего нет:

1. **Случайных мутаций** — тех самых, что ломают и делают растение. В данных
   сайта их нет вообще: дерево эволюции показывает только `mutationPrototypes`
   (переход вида в вид), а таблица `randomMutations.yml` — потенция, урожай,
   выносливость, Unviable, Kudzu, Seedless — не извлекается ни для одного форка.
2. **Вероятностей.** Игрок не знает, что `Unviable` (0.109) втрое вероятнее
   `ChangePotency` (0.036) — то есть что мутаген статистически чаще убивает
   линию, чем улучшает её.
3. **Потолков.** Ни одного числа: Robust Harvest упирается в 50 и после этого
   ест урожай, потенция выше насыщения химии бесполезна, у мутаций своя
   лестница с разворотом наверху.

Существующий `BOTANY_GUIDE` ([config.py:2082](../../config.py)) эти пробелы не
закрывает, а частично дезинформирует: «Robust Harvest boosts potency» без
упоминания потолка 50, порога Seedless на 30 и потери урожая.

Отдельная проблема — **разбивка по форкам**. Сайт обещает per-fork правду, а
ботаническая механика разошлась между форками сильнее, чем химия: апстрим
переписал ботанику 2026-08-08 (PR #44576), и форки живут по разные стороны
этого рефактора.

## Что показывает раздел

Две сворачиваемые секции на вкладке Botany, рядом с «🌱 Plant Evolution»:

1. **🧬 Случайные мутации** — таблица активного форка: какие мутации бывают,
   с каким шансом, что они меняют, в каких пределах, обратимы ли, действуют на
   растение или на плод. Плюс свёрнутая сводка по всем форкам.
2. **⚙️ Потолки механик** — курируемый блок движковых констант: Robust Harvest,
   дозировка мутагена и такты, формула потенция → химия, здоровье и выносливость.

## Данные

### Источник

`Resources/Prototypes/Hydroponics/randomMutations.yml` — **проверено 2026-09-12:
файл существует во всех 21 репозиториях `FORK_REGISTRY`** (запрошен raw по
`repo`/`branch` каждого форка). Отдельного курирования путей не требуется, но
парсер обязан пережить его отсутствие (см. «Риски»).

В `FORK_REGISTRY` добавляется класс файлов по образцу `seed_files`:

```python
"mutation_files": ["Resources/Prototypes/Hydroponics/randomMutations.yml"],
```

### Две схемы, одна запись

Файл существует в двух несовместимых схемах — это и есть главный
форк-различающий признак, и он **определяется по содержимому, а не по списку
форков**: наличие `applyRange` → новая модель, наличие `steps:` → старая.

| Что | Старая схема (`ladder`) | Новая схема (`range`) |
|---|---|---|
| Цель | `targetValue: Potency` | `targetComponent: Plant` + `targetDataField: Potency` |
| Пределы | `minValue` / `maxValue` | `applyRange.min` / `applyRange.max` |
| Шаг | `steps: 5` → сетка из 6 ступеней, значение **снапается** на неё | `up` / `down` как отдельные эффекты (`±15`) |
| Булев трейт | `targetValue: Seedless` (переключатель) | `PlantChangeTraits` + `trait:` (по умолчанию `Toggle`) |
| Срабатываний за цикл | ровно одно, `p = min(baseOdds × severity, 1)` | цикл `while (baseOdds × severity > triggers)` — при severity 25 `Unviable` срабатывает дважды гарантированно |

Канонический вид записи после парсинга:

```json
{
  "id": "ChangePotency",
  "family": "potency",
  "table": "RandomPlantMutations",
  "odds": 0.036,
  "kind": "stat",
  "target": "Potency",
  "range": [30, 100],
  "step": {"model": "ladder", "steps": 5},
  "persists": false,
  "appliesToPlant": true,
  "appliesToProduce": true,
  "reversible": false
}
```

Для новой схемы `step` — `{"model": "range", "up": 15, "down": -15}`.
`reversible: true` ставится булевым трейтам: их эффект — переключатель, то есть
пойманный `Unviable` снимается повторным срабатыванием (практически важно).

### Ключевание по таблице

В одном файле может быть **несколько списков**. У ванили их два:
`RandomPlantMutations` (27 записей, `ignoreMutationMod: false`) и
`EvilPlantMutations` (1 запись, `ignoreMutationMod: true`) — вторая таблица
триггерится не мутагеном и в общий счёт входить не должна. Записи ключуются
парой (id таблицы, имя мутации); сводка сравнивает одноимённые таблицы.

### Канонизация эпох (`family`)

Без неё сравнение форков состоит из шума. Проверено 2026-09-12 по именам
мутаций во всех форках:

| Старая эпоха | Новая эпоха | `family` |
|---|---|---|
| `ChangeIdealHeat`, `ChangeHeatTolerance` | `ChangeLowHeatTolerance`, `ChangeHighHeatTolerance` | `heat` |
| `ChangeLigneous` | `Lignification` | `ligneous` |
| `ChangeTurnIntoKudzu` | `Kudzufication` | `kudzu` |

Сравнение форков идёт **по `family`**, а не по именам. Соответствие внутри
семейства `heat` не один-к-одному (старая пара «идеальная температура +
допуск» против новой пары «нижний + верхний допуск») — поэтому `family`
помечается флагом `split: true`, и в сводке такое расхождение показывается как
«другая эпоха», а не как «мутация добавлена/убрана».

### Что даёт сравнение после канонизации

Замер 2026-09-12 (21 форк, таблица `RandomPlantMutations`):

| Форк | Модель | Записей | Реальное отличие |
|---|---|---|---|
| vanilla, corvax, cmu, rucm, deadspace, trauma | `range` | 27 | — |
| adt, sunrise, goob, deltav, fish, funky, harmony, monolith, omu, starlight, carpmosia, rmc14, stories_cm | `ladder` | 27 | только эпоха |
| frontier | `ladder` | 25 | нет газовых мутаций (`ChangeExudeGasses`, `ChangeConsumeGasses`) |
| misfits | `ladder` | 18 | нет `Sentient`, `Slippery`, `Kudzufication`, газовых, обоих давлений и температурных (замены старой эпохи тоже нет) |

У двух мутаций, проверенных при замере, `baseOdds` совпал во всех 21 форке
(`ChangePotency` 0.036, `Unviable` 0.109). Это результат замера, а не допущение
парсера: все значения извлекаются из файла форка и ни при каких условиях не
наследуются из ванили.

### Хранение

Дельтами, не 21 копией: база — ванильная таблица, форк — `{model, add[],
remove[], override{}}`. Оценка объёма 20–30 КБ, поэтому кладётся **прямо в
`data.json`** новым ключом `plantMutations` (схема +1 минорная). Отдельный файл
(по образцу `ordnance/<fork>.json`) отклонён: он потребовал бы записи в
whitelist `deploy.yml` и runtime-fetch ради экономии, которая на фоне 3.8 МБ
`data.json` не различима.

Дельта-структура — она же источник сводной таблицы: «что уникального у форка»
это буквально его `add`/`remove` после канонизации.

## Курируемый блок «Потолки механик»

Движковые константы живут в C#, который экстрактор не качает. Поэтому — новый
`BOTANY_MECHANICS` в `config.py` рядом с `BOTANY_GUIDE`, с записью в
`sources.py` (tier `community`, дата сверки, список C#-файлов апстрима).

Четыре блока:

1. **Robust Harvest** — `+3` за тик до потолка `PotencyLimit = 50`; выше порога
   `PotencySeedlessThreshold = 30` растение становится Seedless; при потенции
   ≥ 50 каждое применение — 10 % шанс `yield − 1` (до 1).
   Источник: `RobustHarvestEntityEffectSystem.cs` (+ `RobustHarvest.cs` в
   `Content.Shared` — поля `PotencyLimit`, `PotencyIncrease`,
   `PotencySeedlessThreshold`).
2. **Дозировка и такты** — реагенты метаболизируются каждые `UpdateDelay = 3 с`
   (за тик расходуется 1 ед. каждого реагента, эффект срабатывает один раз и
   **не масштабируется от количества**), рост и мутации — каждые
   `CycleDelay = 15 с`. Отсюда правило: *N единиц мутагена в лотке = severity N
   к ближайшему циклу роста*; severity клампится в `MaxMutationLevel = 25`,
   множитель `MutationMod` — в 3.
   Источник: `PlantHolderComponent.cs`, `PlantHolderSystem.UpdateReagents`,
   `BasePlantAdjustAttributeEntityEffect.cs`.
3. **Потенция → химия** — `amount = clamp(Min + Potency / PotencyDivisor, Min,
   Max)`; отсюда насыщение `P_sat = (Max − Min) × PotencyDivisor`. Показывается
   как правило плюс примеры из уже извлечённых `plants[].chemicals`
   (Ambrosia Deus — 70, мак — 95, крапива — 96), то есть числа примеров берутся
   из данных, а не из текста. Выше насыщения потенция пустая — кроме выделения
   газов (масштабируется линейно без потолка) и компоста (`Potency / 2.5`).
   Источник: `BotanySystem.Produce.cs`, `PlantHolderSystem` (exude/компост).
4. **Здоровье и выносливость** — реген примерно `+1` за цикл при воде > 10 и
   питании > 5; аммиак `+0.5` за тик; диэтиламин с шансом 10 % за тик даёт
   `+1 Endurance` и `+1 Lifespan` **без верхнего предела**; криоксадон
   откатывает возраст. Оговорка про ladder-форки: мутация `ChangeEndurance`
   снапает выносливость обратно в диапазон 50…150, поэтому диэтиламин качают
   после того, как мутаген убран.
   Источник: `PlantGrowthSystem`/`PlantHolderSystem.Update`,
   `PlantDiethylamineEntityEffectSystem.cs`, `PlantCryoxadoneEntityEffectSystem.cs`.

Блоки 1–2 **ветвятся по эпохе активного форка автоматически** (эпоха берётся из
извлечённых данных): для `ladder` показывается лестница потенции
30/44/58/72/86/100 с шансом шага вверх `1 − n/5` и разворотом на 100; для
`range` — `±15` с вероятностью вверх `1 − (P − 30) / 70`.

Существующий `BOTANY_GUIDE` переписывается: убирается неверная фраза про Robust
Harvest, добавляется ссылка на новые секции. Тексты остаются раздельными
документами — блок гайда про свабы, блок механик про числа.

## UI

Обе секции — `batch-section` + `[data-collapsible]` с собственным
`data-collapse-key`, по образцу «Plant Evolution». Источник форка — уже
существующий `activeSource`; при `all` показывается ваниль с явной пометкой.

**🧬 Случайные мутации** (бейдж Verified, зелёный):

| Колонка | Содержимое |
|---|---|
| Мутация | локализованное имя + описание эффекта |
| Что меняет | цель и направление (`Потенция 30…100`, `трейт Unviable`) |
| Шаг | `лестница: 6 ступеней` или `±15` — по модели форка |
| Обратима | да для булевых трейтов |
| На плод | `appliesToProduce` |
| Шанс за цикл | три колонки: при 1 / 5 / 25 ед. мутагена |

Колонки шанса — это `baseOdds × severity` с клампом в 1.0; для `range`-форков,
где апстрим допускает многократное срабатывание, значение выше 1 показывается
как «гарантированно ×N». Сортировка по убыванию шанса — тогда `Unviable`
(10.9 % при 1 ед.) стоит над `ChangePotency` (3.6 %), и главный вывод виден без
чтения.

Внутри — свёрнутый подблок **«Все форки»**: форк · модель · число записей ·
отличия после канонизации · форк-реагенты с ненулевым `PlantAdjustPotency`
(Carpmosia `Saltpetre` +1 без потолка, Trauma `ReaperDelight` +1 ценой −5 hp и
+15 токсинов) — последнее берётся из уже извлечённых `plantEffects`.

## Решения по scope

- **Скрейп C#-констант по каждому форку** — отклонён пользователем (вариант B).
  Эпоха определяется по схеме YAML, чего достаточно для ветвления текстов; сами
  константы курируются один раз по ванили. Пересмотреть, если найдётся форк,
  правящий `PotencyLimit` в коде.
- **Калькулятор шансов** (цепь Маркова по лестнице, ожидаемое число циклов до
  потенции 86/100, риск Unviable при выбранной дозе) — отклонён как вариант C.
  Практическая часть покрыта тремя колонками «шанс при 1/5/25 ед.». Кандидат в
  backlog серии.
- **Отдельная страница `botany.html`** — отклонена: +страница в деплое, sitemap,
  `sw.js`, i18n и туториале ради контента, который помещается в две секции.
- **Строка в Fork Diff** («переехал на другой сервер — что с ботаникой») —
  отложена: сводная таблица закрывает тот же вопрос без изменения второго таба.

## Риски

1. **Форк переложит или удалит файл.** Загрузка обязана не падать: нет файла →
   запись в `warnings` и форк в сводке помечается «данных нет» (а не молча
   наследует ваниль).
2. **Дрейф апстрима.** Форки мигрируют на новую модель со временем; схема
   определяется по содержимому при каждой регенерации, хардкода списков нет.
3. **Расхождение курируемого блока с кодом.** Дата сверки и пути файлов — в
   `sources.py`; при следующем аудите блок перепроверяется по тем же путям.
4. **Конфликт с серией P.** Параллельная сессия правит те же файлы; D7
   стартует с `git pull`/ребейза на её состояние и коммитит только свои файлы.
