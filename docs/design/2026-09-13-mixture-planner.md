## R14 — баки и канистры только через мензурку

**Модель.** Флаг строки набора переименован по смыслу: `fits` = `FitsInDispenser`
(раздатчик **и** плитка). Сохранённые наборы со старым `heatable` читаются как
`fits`. Подпись в панели — «в раздатчик и на плитку».

**Наполнение ёмкости без `fits`** (бак, канистра) реагентами из раздатчика идёт
через **мерную посуду**: самую большую пустую ёмкость с `fits`, кроме самой
целевой. Один реагент — отдельные заходы: `заходы = ⌈объём / размер мерной⌉` на
каждую волну. Одна мензурка на несколько реагентов не наливается, чтобы реакция
не началась в мерной посуде. Мерной посуды нет или вся занята продуктами —
нехватка «нужна пустая мензурка, чтобы отмерить».

**Переливание промежуточного продукта** из ёмкости A в ёмкость B: если хотя бы
одна из них с `fits`, переливание прямое (1 заход). Если обе без `fits` (бак →
бак), нужна пустая переносная ёмкость с `fits`: `заходы = ⌈объём / её размер⌉`.
Нет такой — нехватка «нужна пустая мензурка, чтобы перенести».

**Критерий выбора** (rollout R10): `нехватка → смешивания → переливания →
заходы → ёмкости`. Нехватка теперь идёт первой: план, где не хватает мерной
мензурки, не должен побеждать полный. Цепочка в бак по-прежнему выигрывает у
мензурки при равных смешиваниях, потому что экономит переливание продукта
(Криоксадон 540u: бак — 2 смешивания, 0 переливаний, 4 захода; мензурка для
первого шага — 2 смешивания, 1 переливание, 3 захода). **Оракул** сравнивает пару
`(нехватка, смешивания)`.

## R15 — порядок действий, формулировки, шрифт, баки без выбора форка

**Порядок действий.** Карточки по ёмкостям уступают место одному нумерованному
списку в порядке выполнения. Каждый шаг — блок с заголовком «N · ёмкость», смена
ёмкости отмечена «↪». Над списком, если ёмкостей больше одной: «Шаги идут по
разным ёмкостям — выполняйте строго по номерам». Внизу — итог и что лежит в
каждой ёмкости в конце.

```
1 · Бак 1000u №1
    Налейте в Бак 1000u №1 через Высокоёмкую мензурку 300u №1:
      120u Кислород — 1 заход
      60u Плазма (кат.) — 1 заход
    → 180u Дексалин  ✓ симулятор
2 · Бак 1000u №1
    Долейте в Бак 1000u №1 через Высокоёмкую мензурку 300u №1:
      180u Вода — 1 заход · 180u Кислород — 1 заход
    → 540u Криоксадон  ✓ симулятор
3 · ↪ Высокоёмкая мензурка 300u №1
    Перелейте 150u Дексалин из Бака 1000u №1 в Высокоёмкую мензурку 300u №1
    Из раздатчика: 150u Железо · 150u Кремний
    Нагрейте до >310K
    → 300u Силицид железа  ✓ симулятор
Итог: 3 смешивания · 2 ёмкости · 1 переливание · 4 захода мензуркой
В конце: Бак 1000u №1 — 540u Криоксадон, 60u Плазма; Мензурка №1 — 300u Силицид железа
```

**Формулировки.** Реагент и обе ёмкости называются явно: «Перелейте 150u
Политриновая кислота из Мензурки 60u №1 в Бак 1000u №2». Для этого у каждой
ёмкости пресета хранятся формы «из чего» (родительный) и «во что» (винительный);
у своей ёмкости — «Своей ёмкости / Свою ёмкость».

**Баки без выбора форка.** При источнике «Все» сервер не известен, и панель
показывает переключатель семейства: «CM-серверы: RMC14 · RuCM · CMU · Stories» /
«Станция: ваниль и остальные форки». По умолчанию выбрана CM — так баки видны
сразу. Выбор хранится в сессии. Конкретный форк в «Источнике» задаёт семейство
сам, и переключатель скрыт. В панели всегда есть строка «как это устроено», а при
CM и «Все» — подсказка выбрать RMC14 или RuCM, чтобы рецепты считались по
CM-лекарствам. Панель по умолчанию раскрыта; если её свернуть, это запоминается.

**Шрифт.** Панель и шаги: 0.72–0.73rem → 0.85–0.9rem, подписи и метки
0.62rem → 0.76rem.

## R16 — смеси: модель, количества, совместимость

**Смесь** — компоненты с долями и выход:
- «объём» — итоговые единицы;
- «таблетки» — число таблетниц × 16 таблеток × доза.

Компонент — любой реагент: лекарство варится по плану, раздатчиковый (сахар,
железо) наливается как есть.

**Количества на шаге 5u.** Для долей `p_i` (целые, `P = Σ p_i`):
- компонент `A_i = T · p_i / P` кратен 5, если `T` кратно `L₅ = lcm_i(5P / gcd(5P, p_i))`;
- лестница как в R3: `L₅`, затем целые `L₁ = lcm_i(P / gcd(P, p_i))`, затем точно;
  перерасход не больше max(5u, 25 %).

Примеры: Унга 300u → 315u по 45u; Мера-Бика 240u без изменений.

В режиме таблеток на лестницу ставится **объём одной таблетницы** `B = 16 × доза`,
и доза пересчитывается: Унга по 15u → 245u на таблетницу → таблетка 15.31u.
Загрузка ChemMaster: `k = max(1, min(8, ⌊500 / B⌋))` таблетниц на один буфер.

**Варка.** Компоненты уходят в `planBrew` как цели — каждая квантуется по R3.
Излишек `заказано − A_i` остаётся в ёмкости компонента и показывается остатком.
В конец плана добавляется **шаг смешивания**: забрать ровно `A_i` каждого
компонента (переливания и заходы по R14), раздатчиковые налить, проверить.

**Куда смешивать.**
- «Объём»: самая подходящая пустая ёмкость (баки впереди при равенстве) или волны
  по её объёму, кратные `L`.
- «Таблетки»: буфер ChemMaster 500u, загрузками по `k` таблетниц. Буфер — не
  `fits`: в него заливают из мензурки, вставленной в машину.

Цепочек в шаге смешивания нет: компоненты должны лежать раздельно до конца.

**Совместимость.** `simulateBeaker(содержимое загрузки, 293, форк)` не должен
запускать ни одной реакции. Проверка идёт по активному форку и по всем форкам
семейства:
- CM: RMC14, CMU, RuCM, Stories;
- ваниль: активный форк и ваниль.

Если реакция срабатывает на активном форке — красный блок «смешивать нельзя»:
какая реакция, из чего, что получится, какой компонент убрать. Если на другом
форке семейства — жёлтая строка «на CMU и RuCM → Чёрная слизь». Для этого у
`simulateBeaker` появляется необязательный третий параметр `forkId`; без него
поведение прежнее.

## Риски и допущения

- **Симулятор ≠ движок.** «✓ совместимы (симулятор)», а не «гарантия». Вкладка
  «Симулятор стакана» остаётся для ручной проверки.
- **Один реагент за заход мерной мензурки** — безопасно, но может переоценить
  заходы: опытный химик иногда наливает два нереагирующих вместе. Цифра — верхняя
  граница.
- **Пропорции Унги** — по 1 со слов игроков, подпись в пресете.
- **RuCM ← CMU** — если на сервере владельца Чёрная слизь из Унги не выходит, надо
  править родословную в реестре, а не прятать предупреждение.
- **Параллельные сессии:** перед коммитом общего файла — `git diff -- <файл>`;
  коммит через временный индекс, если в индексе чужие файлы.
