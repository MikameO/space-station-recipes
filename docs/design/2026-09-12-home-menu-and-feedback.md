## Проблема

Платформа выросла из справочника по химии в семь вкладок плюс отдельную
страницу, и внутри вкладок спрятаны подсистемы, о которых снаружи не
догадаться: в Calculator — четыре планировщика (рецепт, смена, симулятор
стакана, обратный поиск), в Maps — режим «что продать» с прайс-листом, в
Ordnance — 22 инкремента работы. Точка входа осталась от версии 1.0: `/`
открывает сетку реагентов, остальное — ряд одинаковых кнопок в таб-баре. Новый
посетитель видит справочник по химии; старый — не узнаёт, что в разделе, куда он
не заходил месяц, появилось что-то новое. Аналитика подтверждает: функции,
о которых не рассказано, не используются.

Обратная связь устроена так, что ею пользуется тот, у кого есть аккаунт GitHub
и десктоп. Игроку без аккаунта, а тем более с телефона, сказать «не хватает
вот этого» некуда. Пассивный канал ничего не приносит — за всё время единицы
issues, при сотнях возвращающихся посетителей.

## Что делается

Три части, одна система:

1. **Оверлей «Разделы»** — карта платформы поверх приложения. Доступен всегда
   кнопкой первым элементом таб-бара (и в шапке `library.html`). Всплывает сам
   на втором визите (карта для вернувшегося новичка) и каждый раз, когда с
   последнего визита обновился хотя бы один раздел — с заголовком «N разделов
   обновились с вашего визита <дата>». Карточка раздела: скриншот-фон под
   скримом, иконка, название, описание, чипы «что внутри»; при непросмотренном
   обновлении — янтарная рамка, точка в углу и одна строка «что нового»; у
   нового раздела — фосфорно-зелёная рамка и «Новый раздел».
2. **Форма идей** — нативная, в CRT-теме, RU/EN, без регистрации: текст и
   необязательный контакт. Открывается из карточки «Предложить идею» в меню, из
   кнопки обратной связи в шапке и из опроса. Заявка уходит через Cloudflare
   Worker и становится GitHub Issue с меткой `idea` — туда, где у проекта живёт
   работа («запрос пользователя» в ROADMAP).
3. **Опрос возвращающихся** — с третьего визита, после минуты активного
   чтения, не в одной загрузке с меню: два вопроса пользователя («Что было
   сложнее всего?», «Чего не хватает?»), ответы — issue с меткой `survey` и
   метаданными визита. Закрыл крестиком — спросим ещё раз через 30 дней; второй
   крестик или отправка — больше никогда.

## Манифест разделов: `sections.json`

Единственный источник правды о том, что есть на платформе и когда что менялось.
Массив записей в порядке показа; читается одним `fetch` обоими страницами и
(в backlog) скриптом, пекущим статический лендинг.

```json
{
  "schema": 1,
  "sections": [
    {
      "id": "botany",
      "weight": "normal",
      "target": "tab:botany",
      "title":  { "en": "Botany", "ru": "Ботаника" },
      "desc":   { "en": "What feeds, heals, mutates or kills plants.",
                  "ru": "Что кормит, лечит, мутирует и убивает растения." },
      "inside": [ { "en": "Effect chips", "ru": "Чипы эффектов" },
                  { "en": "Mutation tree", "ru": "Дерево мутаций" },
                  { "en": "Swab guide", "ru": "Гайд по мазкам" } ],
      "shot": "promo/cards/botany.webp",
      "added": "2026-07-11",
      "updated": "2026-09-12",
      "whatsNew": { "en": "Plant Healing chips and value ranges",
                    "ru": "Чипы Plant Healing и диапазоны значений" }
    }
  ]
}
```

| Поле | Тип | Правило |
|---|---|---|
| `id` | строка, уникальна | Совпадает с `data-tab` вкладки, где применимо; ключ состояния `seen` |
| `weight` | `hero` \| `normal` | `hero` — Reagents и Calculator (ядро по аналитике: 62 % юзеров открывают карточку, 46 % — калькулятор); рендерятся крупнее, с полным набором чипов |
| `target` | строка | Четыре вида, см. ниже |
| `title`, `desc`, `whatsNew` | `{en, ru}` | Тексты для игрока, не для разработчика. `desc` — одна строка, ≤ 90 символов; `whatsNew` — одна строка, ≤ 70 символов, описывает **последнее** изменение |
| `inside` | массив `{en, ru}` | Чипы «что внутри»; hero показывает все, normal — первые три |
| `shot` | путь | WebP в `promo/cards/`; обязателен, проверяется при деплое |
| `added` | ISO-дата | Когда раздел появился; основание бейджа «Новый раздел» |
| `updated` | ISO-дата | Последнее видимое игроку изменение; основание бейджа «Обновлено». **Багфикс — не обновление.** Бамп `updated` + переснятый скриншот + `whatsNew` — часть Definition of Done инкремента, затронувшего раздел, как сейчас бамп `?v=` |

**Виды `target`:**

| `target` | Действие на `index.html` | Действие на `library.html` |
|---|---|---|
| `tab:<id>` | `.tab-btn[data-tab="<id>"].click()` — тот же путь, что у пресетов смены | Переход `./#tab=<id>` — формат `decodeURLState`. Внимание: whitelist `validTabs` сейчас не содержит `botany` (AUDIT C17/B10, инкремент Q1); до Q1 переход с Библиотеки в Ботанику приземляется на Reagents — принимаемая деградация, Q1 закрывает |
| `page:library.html` | Переход | — (текущая страница; карточка помечена «вы здесь») |
| `mode:antag` | Включить режим (`#antagToggle`), затем `tab:antag` | Переход `./#antag=1&tab=antag` |
| `action:feedback` | `window.ChemDBFeedback.open('idea', { source: 'home' })`; пока Worker не настроен — ссылка на GitHub-шаблон (см. фича-флаг) | то же |

**Начальное наполнение** — 11 записей в этом порядке: `reagents` (hero),
`calculator` (hero), `medbay`, `trees`, `botany`, `maps`, `ordnance`, `forkdiff`,
`library`, `antag`, `feedback` (`target: action:feedback`, без `shot` —
пунктирная рамка и голубой акцент, без дат и бейджей). Даты `added`
выставляются по ROADMAP/CHANGELOG (medbay 2026-07-12 A3, botany 2026-07-11 M,
maps 2026-07-12 E2, forkdiff 2026-07-12 B1, ordnance 2026-09-10 O3, library
2026-09-11 G1; для разделов, существовавших до ведения CHANGELOG, — `2026-04-19`,
дата первой записи 3.0.0). Начальные `updated` — дата последнего видимого
игроку изменения по CHANGELOG; бейджи старше 60 дней не показываются, поэтому
точность старых дат не критична.

**Правило 60 дней:** обновление, которому больше 60 дней, бейджем не считается
независимо от состояния посетителя — это уже не новость, а история.

## Состояние посетителя

Три ключа `localStorage`, все с защитой `try/catch` (приватный режим,
переполнение). Если запись недоступна — **все авто-попапы отключены**, а не
«показываем каждый визит» (урок pin-callout: B49).

| Ключ | Содержимое | Владелец |
|---|---|---|
| `chemdb-visits` | `{ n, first, last }` — визит = загрузка спустя ≥ 6 ч от `last`; `n` инкрементируется один раз за загрузку | `home.js` (загружается первым на обеих страницах), экспортирует `window.ChemDBVisits` |
| `chemdb-home` | `{ seen: { id → updated }, autoShow: true, lastAutoShown, introShown }` | `home.js` |
| `chemdb-survey` | `{ done, dismissed, dismissedAt, skippedVisit }` | `feedback.js` |

Семантика `seen`: закрытие оверлея записывает `seen[id] = updated` для всех
разделов манифеста — «видел всё, что показано». Бейдж **«Обновлено»** =
`updated > seen[id]` и `updated` не старше 60 дней. Бейдж **«Новый раздел»** =
`added > visits.first` и `id ∉ seen`. Точка на кнопке «Разделы» = есть хотя бы
один бейдж; гаснет при закрытии оверлея.

**Координация попапов** — один флаг `window.__chemdbPopup` (`null` |
`'home'` | `'survey'`): модуль, который показывает попап, занимает флаг; второй
в этой загрузке не показывается. Туториал флага не знает — его активность
проверяется по `#tut-root.active` и по правилу первого визита.

## Оверлей «Разделы»: вход и поведение

**Вход.** `<button class="tab-link home-btn" id="homeBtn" aria-haspopup="dialog">`
первым элементом `.tab-bar` в `index.html` — не `.tab-btn`: `setupTabs` читает
`dataset.tab` и привязывает обработчики только к `.tab-btn`, `.tab-link` он не
трогает (прецедент — ссылка Library, серия G). Текст `⊞ Sections` / `⊞ Разделы`,
точка `<span class="home-dot" aria-hidden="true" hidden>`; количество
непросмотренного — в `aria-label` кнопки. На телефоне таб-бар скроллится
горизонтально (`overflow-x: auto`), первый элемент виден всегда. На
`library.html` — та же кнопка в `.lib-header-right`.

**Авто-показ** решается на `app:ready` + 800 мс (`index.html`; сетка успевает
отрисоваться, loading-overlay уже снят) или на `DOMContentLoaded` + 800 мс
(`library.html`). Если `app:ready` успел отгреметь до загрузки модуля
(признак — `window.DATA` уже заполнен), модуль решает сразу, не дожидаясь
события. Правила по порядку, первое сработавшее — окончательное:

| # | Условие | Решение |
|---|---|---|
| 1 | `body.companion` · URL содержит deep-link (непустой `location.hash` с параметрами; `#doc=` на Библиотеке) · `#tut-root.active` · `localStorage` недоступен | Не показывать. Точка на кнопке — если есть бейджи (в приватном режиме точки нет: нечего сравнивать) |
| 2 | Первый визит (`visits.n === 1`) | Не показывать — первый визит принадлежит туториалу. Записать `visits.first`, `seen` = текущие `updated` всех разделов |
| 3 | Второй визит и `!introShown` | Показать один раз в режиме **интро**: заголовок «Вот что есть на платформе», без подсчёта непросмотренного; `introShown = true` |
| 4 | Есть бейджи · `autoShow` · `lastAutoShown` не сегодня | Показать в режиме **обновлений**: «N разделов обновились с вашего визита <дата `visits.last` до инкремента>»; `lastAutoShown = today` |
| 5 | Иначе | Точка, если есть бейджи |

Сессионное восстановление вкладки (`ss14_session`) deep-link'ом не считается.

**Разметка оверлея.** `div.home-root[role=dialog][aria-modal=true][aria-labelledby]`
→ `.home-panel` (≤ 1100 px, прокрутка внутри панели, `body` не скроллится):

- шапка: заголовок, подзаголовок (интро / «N разделов обновились…» / пусто при
  ручном открытии без бейджей), тумблер «Показывать при обновлениях»
  (`autoShow`, выключение → цель `home_autoshow_off`), кнопка ×;
- hero-ряд: 2 колонки;
- сетка normal: 3 колонки ≥ 900 px, 2 колонки ≥ 480 px, 1 колонка < 480 px;
- карточка — `<a>` (`page:`) или `<button>` (остальные) с полным доступным
  именем «Ботаника — обновлено 12 сентября: чипы Plant Healing…»;
- закрытие: ×, Esc, клик по подложке; focus-trap внутри панели; фокус
  возвращается на `#homeBtn`.

**Анатомия карточки.**

```
.home-card[.is-hero][.is-updated|.is-new][.is-here]
  img.home-shot[loading=lazy][alt=""]     ← скриншот, object-fit: cover
  .home-scrim                             ← тёмный слева под текстом → прозрачный справа; на hover/focus светлеет
  .home-dot                               ← точка в углу: янтарь (updated) / фосфор (new)
  .home-body
    .home-title  <icon> Название
    .home-desc   одна строка
    .home-chips  чипы inside (hero — все, normal — 3)
    .home-new    «Новое: …  · 12 сен» (янтарь) | «Новый раздел · 11 сен» (фосфор)
```

Рамка карточки: `is-updated` — 1 px `#ffb627`, `is-new` — 1 px
`var(--phosphor)`; без тяжёлого неонового свечения — на CRT-теме оно сливается
с остальным. `prefers-reduced-motion` отключает пульсацию точки. Клик по
карточке: закрыть оверлей → выполнить `target` → цель `home_card {id}`.

## Скриншоты-фоны

- Формат: WebP, ширина 720 px (из кадра 1800×915 → 720×366), качество ~70,
  целевой размер 15–25 КБ; файл `promo/cards/<id>.webp`, 10 штук.
- Исходники — существующие `promo/shot-*.png` для семи разделов; для
  Ordnance, Library и Antag снимаются в превью в том же кадре 1800×915.
  Конвертация — Pillow, команда фиксируется в плане (воспроизводимо).
- Загрузка: `loading="lazy"`, **не** в PRECACHE (офлайн оверлей показывает
  карточки без фона — скрим и текст читаются сами по себе).
- Правило обновления: скриншот раздела переснимается вместе с бампом `updated`.
  `scripts/check_sections.py` предупреждает, если `updated` новее mtime/коммита
  скриншота.

## Форма идей и опроса: `feedback.js`

Один компонент, два режима; открывается из трёх мест: карточка
`action:feedback` в меню, `.feedback-btn` в шапке (перехват клика — без JS
ссылка на GitHub Issues ведёт туда же, что и раньше), попап опроса.

| | Режим `idea` | Режим `survey` |
|---|---|---|
| Поля | `text` — обязателен, 10–2000 символов · `contact` — необязателен, ≤ 80 | `hardest` — «Что было сложнее всего?», над полем чипы разделов из манифеста (тап подставляет название в начало поля) · `wanted` — «Чего не хватает на платформе?» · `contact`. Хотя бы одно из двух текстовых полей непустое, каждое ≤ 2000 |
| Скрытая мета | `page` (`index`/`library`), `lang`, `fork` (активный source), `tab`, `visits`, `device` (`mobile` при `max-width: 700px`, иначе `desktop`), `data` (`meta.schemaVersion`) | то же + `chips` (выбранные разделы) |
| Вид | Модальная карточка в CRT-теме (`role=dialog aria-modal`) | Десктоп — карточка 380 px внизу справа, **не модальная** (`aria-modal="false"`, работе не мешает); телефон — нижний лист |

Под формой в обоих режимах одна строка: *«Заявка публикуется как issue на
GitHub — публично. Не оставляйте личных данных; для связи лучше ник в
Discord»*. Вторая строка — «или открой issue сам» → prefilled-ссылка на
`issues/new?template=idea.yml` (соответственно `survey.yml`) с текстом полей в
`body`.

**Защита от спама и ошибок:** honeypot `<input name="website">` (пустой),
минимум 3 с между открытием и отправкой, 1 отправка в минуту на режим
(localStorage), `navigator.onLine === false` → тост «Нет сети — попробуйте
позже», без очереди. Успех → тост «Спасибо! Заявка #123» со ссылкой на issue
(публичный — ссылку показывать можно). Ошибка → текст ошибки под формой +
GitHub-ссылка как запасной путь; цель `feedback_fail {mode, code}`.

**Фича-флаг:** константа `FEEDBACK_URL` в `feedback.js` (переопределяется
`window.CHEMDB_FEEDBACK_URL` для dev). Пока пустая — формы не рендерятся:
карточка меню и `.feedback-btn` ведут на GitHub-шаблон, опрос не показывается
(нечем принять ответ). Это позволяет выкатить меню (H1) до настройки Worker'а
(H2), а H3 — после H2.

## Worker: `worker/index.js`

Cloudflare Worker (бесплатный план), один маршрут `POST /submit`, ответ JSON.

```json
// запрос
{ "kind": "idea" | "survey",
  "text": "…",                       // idea
  "answers": { "hardest": "…", "wanted": "…" }, "chips": ["ordnance"],  // survey
  "contact": "",
  "meta": { "page": "index", "lang": "ru", "fork": "rucm", "tab": "calculator",
            "visits": 5, "device": "desktop", "data": "3.10.0" },
  "hp": "", "t": 4200 }
// ответ
{ "ok": true, "number": 123, "url": "https://github.com/MikameO/space-station-recipes/issues/123" }
```

Порядок проверок и коды: `Origin ∈ ALLOWED_ORIGINS` (переменная окружения,
prod = `https://mikameo.github.io`; dev — локальный origin через
`wrangler dev --var`) иначе 403 · `Content-Type: application/json` и тело ≤ 8 КБ
иначе 400/413 · `hp` пустой, `t ≥ 3000`, `kind` из множества, длины полей в
границах иначе 400 · Rate Limiting binding 5 запросов/мин на IP иначе 429 ·
`POST /repos/MikameO/space-station-recipes/issues` с
`Authorization: Bearer ${GITHUB_TOKEN}`; сбой GitHub → 502. `OPTIONS` —
preflight с теми же origin'ами.

Issue: заголовок `[idea] <первые 60 символов в одну строку>…` или
`[survey] визит 5 · ru · rucm`; метки `idea`|`survey` + `from-site` (создаются
в репозитории заранее); тело — markdown: текст(ы), затем таблица меты и
контакт, подпись «Отправлено с сайта через форму обратной связи». IP не
пишется ни в issue, ни в логи.

Секрет `GITHUB_TOKEN` — fine-grained PAT владельца только на этот репозиторий,
только `Issues: Read and write`, хранится как секрет Worker'а
(`wrangler secret put GITHUB_TOKEN`). В репозитории — `worker/index.js`,
`worker/wrangler.toml` (имя, `compatibility_date`, `[vars] ALLOWED_ORIGINS`,
binding rate-limit); порядок настройки — комментарий в шапке `wrangler.toml`
и подраздел в `README.md` (отдельных `.md` не создаём — правило проекта);
секретов в репозитории нет. Деплой — `wrangler deploy` владельцем вручную; CI-деплой
Worker'а — в backlog.

Уведомления владельцу — штатные GitHub-нотификации о новых issues; отдельного
канала не нужно.

## Опрос: триггер и режим B

Проверка на `app:ready` (или `DOMContentLoaded` на Библиотеке), затем таймер
**60 с видимости** вкладки (`document.visibilityState === 'visible'`, фон не
считается). По истечении показать, если **все** верно:

- `FEEDBACK_URL` задан; `visits.n ≥ 3`; `!survey.done`;
- `survey.dismissed === 0`, либо `dismissed === 1` и
  `now − dismissedAt ≥ 30 дней` (режим B);
- `survey.skippedVisit !== visits.n` (в этом визите уже уступили меню);
- `window.__chemdbPopup === null`, нет deep-link, не companion, `#tut-root` не
  активен, `localStorage` доступен.

Если в момент срабатывания таймера меню открыто или флаг занят — записать
`skippedVisit = visits.n` и не пытаться до следующего визита. Крестик →
`dismissed++`, `dismissedAt = now`, цель `survey_dismiss {n}`. Отправка →
`done = true`. Показ → цель `survey_shown {n}`.

## i18n и доступность

- Тексты разделов — из манифеста по `window.I18N_LANG`; строки интерфейса
  («Разделы», «Показывать при обновлениях», заголовки формы, тосты, ошибки)
  — EN в разметке, RU через словарь `i18n.js` (правило проекта: не писать
  неизменённый `nodeValue` — иначе цикл MutationObserver). Переключение языка
  перерисовывает оверлей и формы.
- Оверлей: `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, focus-trap,
  Esc, возврат фокуса; карточки — нативные `<a>`/`<button>` с полным именем;
  точка и скриншот `aria-hidden`/`alt=""`; `prefers-reduced-motion`.
- Форма: `<label for>` у каждого поля, ошибки через `aria-live="polite"`,
  honeypot вне порядка табуляции (`tabindex=-1`, визуально скрыт, не
  `display:none` — боты заполняют и такое); опрос — `aria-modal="false"`.
- `.feedback-btn` получает `aria-label` (закрывает B76) — остальная судьба
  кнопки в шапке (скрытие < 480 px, B38) — Q4, здесь не трогаем: на телефоне
  форму открывает карточка меню.

## Решения по scope (пользователь, 2026-09-12)

1. **Вход — D + авто-показ по событию**, не отдельная страница и не замена `/`:
   78 % визитов возвращающиеся, лишний клик каждому — неприемлем; deep-links и
   share-ссылки не ломаются.
2. **Источник обновлений — ручной манифест**, не парсинг CHANGELOG (инженерный,
   по сериям, не по разделам) и не git (любая опечатка зажгла бы бейдж). Одна
   строка «что нового» на раздел.
3. **Фон карточек — скриншоты** (вариант A), несмотря на предупреждение о
   читаемости и весе; компенсация — скрим, WebP 720 px, lazy, правило
   пересъёмки. Вариант B (SVG-мотивы) и гибрид отклонены.
4. **Доставка — своя форма → Cloudflare Worker → GitHub Issue.** Почтовые
   сервисы (Web3Forms/Formspree) и Google/Яндекс Формы отклонены: первые не
   трекаются, вторые — чужой UI и риск блокировки для RU-аудитории. Идеи и
   опрос — в одно место с метками `idea`/`survey`.
5. **Опрос — режим B:** визит = ≥ 6 ч; показ с 3-го визита после 60 с
   видимости; не в одной загрузке с меню; после × — одна повторная попытка через
   30 дней.
6. **Архитектура — два модуля + манифест + Worker**, ноль правок `app.js`
   (параллельные сессии активно его правят). Статический `home.html` из
   манифеста (SEO) — backlog серии.
7. **Не делаем сейчас:** Turnstile/CAPTCHA (honeypot + rate-limit достаточно
   на текущем трафике), очередь офлайн-отправок, «история изменений» на
   раздел, Discord-вебхук из Worker'а, CI-деплой Worker'а.

## Верификация (DoD по инкрементам)

Общее для каждого инкремента: консоль чистая на обеих страницах; 375 px — без
горизонтального overflow; `check_sections.py` и проверка ссылок `deploy.yml`
зелёные локально; cache-bust по §0.2; коммит; после пуша — `curl` новых
ресурсов → 200.

**H1 — манифест, скриншоты, оверлей, бейджи.**
Чистый профиль (очищенный `localStorage`): первая загрузка — только туториал,
меню не всплыло, точка не горит. Подкрутить `chemdb-visits.last` на −7 ч,
перезагрузить — визит 2 → меню-интро один раз; закрыть, перезагрузить — не
всплывает. Поднять `updated` у двух разделов в манифесте (одному поставить
`added` > `visits.first`) → точка на кнопке, янтарная и зелёная рамки, строки
«что нового»/«Новый раздел», авто-показ с «2 раздела обновились с вашего визита
<дата>»; закрыть → точка погасла; перезагрузить → не всплывает (сегодня уже
показывали); тумблер off → при новом бампе не всплывает, точка горит. Все виды
`target` работают с обеих страниц (`tab:`, `page:`, `mode:antag`,
`action:feedback` → GitHub-ссылка, пока флаг пуст). Deep-link `#r=…` → меню не
всплывает. Companion → кнопки нет. RU/EN переключение перерисовывает тексты.
Скриншоты: 10 WebP ≤ 25 КБ, `loading=lazy`. Скриншот результата на 1366 и
375 px.

**H2 — форма, Worker, шаблоны issues.**
`wrangler dev` с локальным origin → отправка из формы (оба входа: карточка,
кнопка в шапке) создаёт issue с метками `idea`+`from-site`, телом и метой
(тестовый issue закрывается); honeypot заполнен → 400 и текст ошибки под
формой; origin чужой → 403; шестая отправка за минуту → 429; текст 5 символов —
клиентская валидация, запрос не уходит; офлайн (DevTools) → тост «Нет сети».
Ссылка «или открой issue сам» открывает prefilled-шаблон. Телефон 375 px —
модалка помещается, клавиатура не скрывает кнопку. Метрика: `feedback_open`/
`feedback_submit` видны в дебаг-режиме счётчика.

**H3 — счётчик визитов, опрос.**
`chemdb-visits.n = 3`, `chemdb-survey` пуст, `FEEDBACK_URL` задан → через 60 с
видимости (фоновая вкладка не считает) попап внизу справа; чип раздела
подставляет название; отправка → issue с меткой `survey`, заголовок
`[survey] визит 3 · …`, `done = true`, больше не показывается. Сброс, × →
`dismissed = 1`, `dismissedAt`; сдвинуть `dismissedAt` на −31 день → показ;
второй × → `dismissed = 2`, больше никогда. Меню открыто в момент таймера →
`skippedVisit = n`, опрос не показан, в том же визите не повторяется. 375 px →
нижний лист.

**H4 — проверка манифеста, цели Метрики, документация.**
Намеренно убранный `shot` → `check_sections.py` красный; `target: tab:nope` →
красный; `updated` новее скриншота → предупреждение. Цели зарегистрированы
(после «ок»), `track()` ↔ реестр совпадают. README (таблица фич: строка
«Sections menu», «Feedback»), CHANGELOG (серия H), ROADMAP (серия H со
статусами).

## Риски и допущения

- **Спам в issues.** Rate-limit на IP + метка `from-site` для массового
  закрытия + Worker выключается одной командой; Turnstile — в backlog, если
  понадобится.
- **Устаревшие скриншоты.** Предупреждение `check_sections.py`; правило DoD.
  Остаточный риск — владелец игнорирует предупреждение; тогда карточка
  «обновлено» показывает старый интерфейс — деградация косметическая.
- **Сброс `localStorage`** (чистка браузера, другой браузер) обнуляет визиты
  и «видел» — посетитель получит интро и бейджи заново. Принимаем.
- **Приватный режим** — попапов нет вовсе (не «каждый визит»). Принимаем.
- **`validTabs` без `botany`** — переход с Библиотеки в Ботанику до Q1
  приземляется на Reagents.
- **GitHub API квота** — 5000 запросов/час на PAT; форма не приблизится.
- **Cloudflare** — внешний аккаунт и секрет у владельца; при недоступности
  Worker'а форма показывает ошибку и GitHub-ссылку, меню не зависит от него.
- **Параллельные сессии** правят `index.html`, `style.css`, `sw.js`
  одновременно с этой серией: правки в этих файлах — точечные, после
  `git status`/mtime-чека, коммиты — только своих файлов (правило §0.3 ROADMAP).
- **Заголовок «с вашего визита <дата>»** использует `visits.last` до
  инкремента; при первом показе после долгого перерыва дата может быть старше
  60 дней, а бейджи — только за 60 дней: формулировка «N разделов обновились
  за последнее время» в этом случае.
