## Проблема

Внутриигровая тактическая карта RMC14 и Stories устроена так (проверено по
исходникам 2026-09-13): рисовать линии и метки можно только с tacmap-компьютера
(консоль CIC, консоль десантного корабля, планшет CO) при навыке Leadership 2,
которого у SL нет (у SL — 1); публикация холста заменяет его целиком с общим
кулдауном 240 с и объявлением ARES; рядовые и SL видят позиции, замороженные на
момент последней публикации; инструменты — семь цветов, линии и текстовые
метки. Слоя запросов, ресурсов и таймеров нет. Открытый черновой PR 9194
«Tacmap Rework» добавляет слои отрядов без кулдауна, но и там слои не двигают
точки, а сам PR стоит с июля.

Офицер в игре окружает себя окнами: карта с позициями, консоль наблюдения,
вид за морпехом, чат; всплывающие окна помогают, но второй монитор становится
нормой. Внешний слой планирования и координации, который дополняет игру, а не
дублирует её, и есть предмет этой спеки.

Правила серверов делают такой слой запрещённым без санкции: RMC14 (Zero
Tolerance, «Information Fairness») запрещает делиться внутриигровой
информацией любыми внешними средствами, разрешая явно только «внешнюю
программу для расчёта координат»; Space Stories CM (правило 3) называет
нарушением сообщение о позициях противника через внешние средства связи;
Corvax CM запрещает стороннее ПО ради преимущества. Отсюда ворота: комната
существует только для серверов, давших письменное «да», и никогда не
добывает информацию сама.

## Что делается

**В объёме:**
- комната на раунд: создание, код на бумаге и по рации, срок жизни, закрытие,
  экспорт;
- реестр должностей с удостоверением словом или заранее выданными кодами,
  вход по ходу операции, передача должности, наблюдатель;
- общие объекты поверх карты: метки, линии и области по контракту T6 с
  автором, слоем, сроком жизни и «почерком» уровня командования; гладкие
  кривые и протяжка мышью; калибровка комнаты;
- запросы удара с состояниями и связкой «Взять цель» с карточками огня серии T;
- доска ресурсов с ручными состояниями и подсказками-отсчётами из констант
  форка;
- политика форка как конфиг: санкция по серверам, должности, уровни, права,
  такты, лимиты; пакет для администрации Stories;
- защита: лимиты, стоп-лист, ссылка наблюдателя, журнал, чистка по должности.

**Вне объёма (принципиально):** живые позиции своих или чужих; любое чтение
памяти, трафика или экрана игры; аккаунты и персональные данные; чат и голос;
реплей раунда (в апстриме есть в PR 9194); планирование огневых задач КАС
(PR 8890); вклад в апстрим (вариант B, см. открытые вопросы).

## Сценарий раунда

1. **Брифинг.** CO или SO открывает tactical.html на планете раунда, нажимает
   «Создать комнату», получает код и текст для бумаги; ссылки наблюдателя по
   умолчанию нет, штаб выпускает её кнопкой, когда её просит модератор.
   Код звучит по командной рации, бумага с кодом (и QR по желанию) лежит на
   столе брифинга. Офицеры входят по коду и берут должности; каждый видит своё
   слово, называет его, штаб подтверждает. Комната блокируется от новых входов.
2. **Высадка.** Первый, кто снял координаты дальномером, публикует калибровку
   комнаты; остальные принимают одним кликом. Штаб рисует план в общий слой:
   маршруты гладкими линиями, сектора областями, подписи.
3. **Бой.** SL ставит метки противника, они тускнеют, если их не подтвердить.
   SL создаёт запрос миномёта по цели; расчёт видит карточку, нажимает
   «Взять цель», координаты уходят в карточку огня из серии T, «Выстрел»
   переводит запрос в «огонь» и запускает отсчёт; «выполнен» ставит расчёт.
   SO держит доску ресурсов: ОБ «перезарядка до», поставка «готова через»,
   пилот сам ставит «облёт» и «вернулся».
4. **По ходу операции.** Погибшего SL сменяет другой игрок: он «стучится» по
   коду, штаб подтверждает его одного, не открывая комнату; прежняя сессия
   снимается. Утечка кода — «сменить код» и снять незнакомых.
5. **Конец раунда.** «Закрыть комнату», экспорт журнала для разбора; через
   шесть часов после последней операции комната исчезает.

## Архитектура и модули

```
tactical.html ── tactical/tactical.js (UI серии T) ── хук window.TacticalRoom ──┐
      │                                                                          │
      ├── tactical/room.js (интерфейс комнаты: панель, реестр, отрисовка чужих   │
      │       объектов, WebSocket-клиент)                                       │
      ├── tactical/room-logic.js (чистая логика: журнал, слияние, политика,     │
      │       фильтры, отсчёты; Node-тесты через vm, как logic.js)               │
      ├── tactical/policy/<форк>.json (санкция, должности, уровни, права)       │
      └── localStorage: chemdb-tactical:room/<код>:<client>, room-current:<client> │
                                                                                 │
worker/index.js (роутер) ── worker/room/ (Durable Object «Room»: WebSocket с    │
      Hibernation API, журнал и объекты в SQLite объекта, TTL, лимиты) ─────────┘
```

- Комната живёт в новых файлах. **Шов** со страницей — три правки в одном
  коммите в свободное окно серии T: тег скрипта и стили в `tactical.html`,
  слот панели в `aside`, хук `window.TacticalRoom` в `tactical/tactical.js`.
  Хук обязан: сообщать комнате о своих объектах (метка, фигура, выстрел,
  калибровка), рисовать чужие объекты на холсте (через `mapview` с почерком
  уровня), принимать цель в карточку огня (`takeTarget`) и сообщать о
  «Выстреле» (`fired`). До шва инкременты V1–V4 не трогают страницу.
- Политика импортируется Worker'ом как JSON-модуль из `tactical/policy/` при
  сборке и отдаётся страницей как файл: одна копия в репозитории. Worker
  отдаёт `GET /policy/<форк>` с хешем; страница сравнивает со своим файлом и
  при расхождении переводит комнату в «только чтение: политика обновляется».
- Образцы в репозитории: чистая логика на `window.*` с Node-тестами
  (`library.js`, `tactical/logic.js`); Worker с тестами
  (`worker/index.js`, `scripts/test_feedback_worker.mjs`); отдельная страница
  с `?v=` (`tactical.html`).

## Жизненный цикл комнаты и удостоверение

- **Создание.** Только на форке и сервере из списка санкции. Сервер выдаёт код
  из шести символов алфавита без похожих знаков (`ABCDEFGHJKMNPQRSTUVWXYZ23456789`)
  и секрет администратора; токена наблюдателя при создании нет (см. «Наблюдатель»).
  Комната привязана к форку и
  планете; срок жизни — шесть часов после последней операции; «Закрыть
  комнату» запрещает операции, экспорт остаётся до истечения срока.
- **Бумага и рация.** Текст для внутриигровой бумаги: название, код, адрес,
  по желанию QR блочными символами в теге `[mono]` (шрифт движка содержит
  `█ ▀ ▄`; проверка рендера на бумаге — задача V4, запасной вариант — только
  код).
- **Вход и удостоверение.** Офицер вводит код, видит реестр должностей и
  берёт свободную. Сайт показывает ему слово подтверждения из словаря коротких
  слов (без омонимов и похожих по звучанию), штабу — «SO: ждёт, ФАЗАН». Слово
  произносится по рации или пишется на бумаге; подтверждает любой из штаба
  (право `confirmJoin` в политике). До подтверждения — только чтение. Второй
  способ: администратор печатает на бумагах отрядов одноразовые коды
  должностей; такой код подтверждает сразу.
- **Вход по ходу операции.** Пока комната закрыта, новый офицер всё равно
  вводит код и «стучится»: штаб видит строку со словом и подтверждает одного,
  не открывая комнату. Погибшего сменяет новый игрок той же должности: прежняя
  сессия снимается по бездействию (политика, по умолчанию 20 минут без
  операций и без связи) или вручную.
- **Привязка сессии.** Должность держится за идентификатором клиента и
  секретом в localStorage; переподключение возвращает её. Действия: освободить
  должность (сам), снять (штаб), передать администрирование (XO, SO),
  заблокировать и открыть комнату, сменить код (старый гаснет, сессии
  остаются), закрыть комнату.
- **Наблюдатель.** Отдельная ссылка только для чтения, без должности, со своим
  токеном и ротацией; по умолчанию ссылки нет: штаб выпускает её по запросу
  (действие `observer`), и уходит она только модераторам сервера.
- **Утечка.** Комнаты не перечисляются, вход ограничен по адресу, реестр
  показывает время входа и последней активности; при подозрении — сменить код
  и снять незнакомых.
- **Имена.** Идентичность — должность; позывной персонажа до 20 символов по
  желанию.

## Модель данных и синхронизация

**Объекты** (координаты — тайлы мира, как в T6; игровые — через калибровку):

```
marker  {id, kind:"marker", cat, label, x, y, level, h, at,
         by:{post, squad?}, layer, ttl?, confirmedAt?}
shape   {id, kind:"line"|"area", cat, label, points:[[x,y]…], smooth:bool,
         level, h, at, by, layer}
request {id, kind:"request", type:"mortar"|"ob"|"cas"|"supply"|"medevac"|"other",
         target:{x,y}, note, priority:"normal"|"urgent",
         status:"requested"|"accepted"|"firing"|"done"|"denied",
         by, acceptedBy?, firedAt?, doneAt?, reason?, markerId}
asset   {id, kind:"asset", type:"mortar"|"ob"|"dropship"|"supply"|"medevac",
         label, tile?, owner:{post}, state, until?, shells?:{he,frag,inc,flare},
         shell?, radius?, note?}
member  {client, post, squad?, callsign?, joinedAt, lastSeenAt, confirmed, confirmedBy?}
calibration {offset:[dx,dy], by, at}
```

`cat`, `label`, `x`, `y`, `points`, `h`, `at` совпадают с контрактом T6
(`markers`, `shapes` в `chemdb-tactical:<fork>/<planet>`), поэтому свой объект
публикуется в комнату без преобразования, а чужой рисуется тем же кодом.

**Операции:** `{seq, at, by:{client, post}, op:"put"|"patch"|"del", kind, id,
data, cid}`. Сервер присваивает `seq` и `at`, проверяет право по политике,
рассылает всем. `cid` — клиентский идентификатор для отбрасывания повторов
после досылки. Побеждает операция с большим `seq`; `patch` — поверхностное
слияние полей; `del` оставляет надгробие до конца жизни комнаты.

**Слои:** `shared`, `staff`, `squad:<id>`, `service`, `requests`, `assets`;
у объекта ровно один слой; черновики (`draft: true`) не покидают клиента.
**Такт публикации:** для слоя `shared` политика может задать такт в секундах;
операции в него копятся на сервере и выпускаются по такту, остальные слои
мгновенные. Для Stories по умолчанию такта нет.

**Калибровка комнаты:** объект `calibration`, публиковать могут должности с
правом `publishCalibration`; клиент с иной личной калибровкой видит расхождение
и принимает одним кликом, личная не затирается молча.

**Срок жизни:** метки категории «противник» получают `ttl` из политики
(по умолчанию 600 с); возраст считает клиент, «подтвердить» обнуляет
(`patch confirmedAt`); истёкшие сервер удаляет при построении снимка.

**Сообщения WebSocket.** Клиент → сервер: `hello {code, client, secret?,
since}`, `op`, `admin {action}`, `ping`. Сервер → клиент: `snapshot {objects,
members, calibration, seq, policyHash, locked}`, `op` (один или пачка),
`denied {cid, reason}`, `roster`, `closed`. После разрыва клиент шлёт `since`;
если сервер не может доиграть (журнал обрезан), приходит новый `snapshot`.

**Маршруты Worker:** `POST /room` (создать; тело: форк, сервер, планета, `h`
планеты) → `{code, adminSecret}`, без токена наблюдателя (его по запросу
выпускает штаб, см. «Наблюдатель»); `GET /room/<code>/ws`
(WebSocket, параметры `client`, `secret?`); `GET /room/<code>/observe/<token>`
(WebSocket только чтение); `GET /room/<code>/export?token=` (JSON и текстовая
хронология; токен наблюдателя или секрет администратора); `GET /policy/<fork>`
(хеш и версия). Административные действия (confirm, kick, lock, unlock,
rotate, delegate, close) идут сообщением `admin` по тому же WebSocket: сервер
проверяет право должности по политике, а секрет администратора даёт создателю
права штаба независимо от должности.

**Хранение на сервере:** SQLite объекта комнаты: `ops(seq, at, client, post,
op, kind, id, data)`, `objects(id, kind, layer, data, deleted)`, `members`,
`meta(code, fork, server, planet, h, createdAt, lastOpAt, locked, closed,
adminSecretHash, observerTokenHash, codeGeneration)`. Alarm объекта
удаляет комнату через `roomIdleSec` после `lastOpAt`.

**Хранение на клиенте:** `chemdb-tactical:room/<code>:<client>` = `{code, fork, planet,
me:{client, post, squad, callsign, secret}, seq, objects, members,
calibration, pending:[op…], locked}`; `chemdb-tactical:room-prefs` = `{sounds,
filters, layout}`. Событие `storage` синхронизирует вкладки, как в T6.

**Пределы:** 2000 объектов на комнату, подпись 40, заметка 80, позывной 20,
до 64 вершин на фигуру, 10 операций/с и 60/мин от клиента, сообщение до
8 КБ, снимок отдаётся пачками.

**Экспорт:** JSON `{meta, members, objects, ops}` и текст: хронология по
должностям с игровыми координатами через калибровку комнаты.

## Запросы и доска ресурсов

**Карточка запроса.** Вид, цель (тайл → игровые координаты), кто просит,
заметка, приоритет. Состояния и права:

| Переход | Кто | Примечание |
|---|---|---|
| создать | любая подтверждённая должность по слою `requests` | метка с кольцом на карте |
| снять | автор, пока «запрошен» или «принят» (после принятия — отзыв без выбора причины) | |
| принять / отклонить с причиной | владелец ресурса или штаб | штаб может перекрыть |
| «Взять цель» | владелец ресурса | координаты уходят в карточку огня серии T через хук |
| огонь / в пути | исполнитель; «Выстрел» в карточке огня ставит «огонь» и отсчёт | |
| выполнен | исполнитель или штаб | |
| повторить | автор | новый запрос со ссылкой на прежний |

**Отсчёты-подсказки из констант форка:** миномёт — 9 с до падения от выстрела;
ОБ — 24 с до удара, 500 с перезарядки от удара; поставка — 500 с перезарядки
консоли от запуска; КАС — облёт 100 с (`rmc.dropship_fly_by_time_seconds`,
с поправкой на навык пилота); эвакуация — без отсчёта. Отсчёты считаются от
времени сервера в операции, у всех одинаковые, и ничего не переключают сами.

**Очередь.** Приоритет, затем возраст; фильтр по виду; лента снизу показывает
свежие, вкладка — всё. Расчёту, на чей ресурс пришёл запрос, — повторяющийся
пинг (абзац ниже); новая карточка в ленте три секунды вспыхивает у всех
участников, кроме автора; автор запроса звука не получает, в том числе на
смену его состояния; звук отключается лично.

**Доска ресурсов.** Записи из политики: миномёты (позиция, расчёт, снаряды по
типам, состояние «развёрнут, в пути, уничтожен»); орудие ОБ (боеголовка,
«готов, заряжается, перезарядка до»); десантный корабль («нет пилота или
офлайн, на корабле, летит к LZ, на LZ, облёт, перезарядка» — «облёт» и есть
«КАС в воздухе», все состояния ставит пилот вручную, отсчёт облёта только
подсказка); поставка («готова через», что запрошено); эвакуация (доступна или
нет). Состояние меняет владелец и штаб. Чипы: зелёный готов, янтарный занят,
серый перезарядка, красный недоступен. Запись миномёта хранит текущий снаряд и
радиус кастомного боеприпаса из «Взрывного дела», чтобы карточка запроса
показывала ожидаемую зону поражения этого расчёта.

**Сигнал о новом запросе (владелец, 2026-09-14).** Расчёт, на чей ресурс пришёл запрос, слышит двухтональный пинг в полосе
1,2–2 кГц: он пробивается сквозь гул боя и не режет ухо. У срочного запроса свой рисунок из трёх тонов. Пинг повторяется
каждые 10 секунд (срочный — каждые 5), пока запрос не принят, не отклонён или не снят, либо пока расчёт не нажмёт «Услышал»
на этом запросе; это только локально, на сервер ничего не уходит. Автор, второй офицер штаба и наблюдатель пинг не слышат.
Пока комната заморожена (радиомолчание, рубильник администрации, исчерпанный бюджет), заблокирована или закрыта, пинг
молчит и звучит снова сразу после, если запрос всё ещё ждёт. Громкость «тихо / обычно / громко», по умолчанию громко;
общий выключатель звука остаётся. Если пинг пора сыграть, а браузер держит звук до первого клика, в панели и в ленте
запросов появляется кнопка «Звук заблокирован браузером — нажмите в панели» (в английском интерфейсе
«Sound is blocked by the browser — click the panel»); клик или клавиша в любом месте интерфейса комнаты включает звук.
Заголовок вкладки помечен «● », только пока для этого участника идёт пинг: не после «Услышал» и не при выключенном
звуке. Расписание идёт от секундного такта модуля, без новых таймеров.

## Крайние случаи и защита

- **Связь:** переподключение с нарастающей паузой; строка состояния «на связи,
  переподключение, только чтение, комната закрыта»; операции без связи копятся
  с числом ожидающих; объект комнаты умер — «комната закрыта» и экспорт из
  локальной копии.
- **Конфликты:** последний `seq` побеждает на объекте; удаление сильнее
  правки (надгробие); отмена своей последней операции; штаб удаляет любой
  объект.
- **Хранилище:** нет localStorage — работа в памяти и плашка «не сохранится»;
  время сервера главное, сдвиг часов клиента считается по отметкам сервера.
- **Пределы на сервере:** 10 операций/с и 60/мин от клиента; с одного адреса
  (Rate Limiting binding, как у формы идей) 20 входов в минуту, 3 создания
  комнаты в минуту и 120 запросов в минуту на любой адрес комнаты
  `/room/<код>/…` (`ROOM_RL`); не больше 3 одновременных комнат на ключ сервера
  (`ROOMS_MAX_PER_KEY`, заблокированные и закрытые не считаются) и общие потолки
  комнат в переменных (см. «Поправки»); превышение — отказ с текстом.
- **Содержимое:** пределы длины; управляющие символы вырезаются; разметка и
  ссылки не рендерятся ни на странице, ни в экспорте.
- **Хулиганство:** журнал показывает автора; штаб снимает должность и одним
  действием чистит её объекты; снятая сессия не возвращается без нового
  подтверждения.
- **Отказы по политике:** операция без права возвращается с причиной,
  интерфейс показывает её и не даёт нажать заведомо запрещённое.
- **Приватность:** в состоянии комнаты нет адресов и имён аккаунтов; лимитер
  по адресу живёт отдельно; всё удаляется через шесть часов.
- **Остановка:** стоп-лист серверов в переменных Worker действует мгновенно;
  запись в политике и деплой закрывают вопрос насовсем.
- **Политика разошлась:** хеш Worker'а не совпал с файлом страницы — комната
  только для чтения до перезагрузки страницы.

## Поправки по итогам war-room

Решение [docs/decisions/2026-09-13_tactical-tablet.md](../decisions/2026-09-13_tactical-tablet.md)
и решения владельца от того же вечера меняют разделы выше так (при
расхождении действует этот раздел):

- **Транспорт (раздел «Модель данных»).** Вместо WebSocket — HTTP-опрос
  `GET /room/<code>/ops?since=<seq>` с секретом сессии в заголовке
  `X-Room-Session`; сервер отвечает `Retry-After: 2` при живом запросе и `10`
  в покое, отдаёт `serverNow` в каждом кадре; клиент считает смещение часов
  на `hello` как RTT/2 и рисует `deadlineAt − serverNowEst`. Операции идут
  пачкой `POST /room/<code>/ops`. WebSocket — бэклог. В объекте комнаты нет
  повторяющихся таймеров: один alarm на срок жизни; такт общего слоя по
  умолчанию выключен и при требовании администрации делается одним alarm'ом на
  срок выпуска буфера.
- **Переходы статусов.** `patch` запроса несёт `expectedStatus`; несовпадение
  — `{error: "status", status}` в подтверждении пакета (ответ 200) без записи строк. Состояния запроса:
  `requested → accepted → loaded → firing → done | denied`; `loaded` даёт ОБ две
  строки владельцев («Заряжено» OT, «Выстрел» SO). Признаки — массив `flags`
  (`beacon`), остальное в `notes`; новых скаляров в объекты не добавляется.
- **Вход и удостоверение (раздел 2).** Основной путь — лист брифинга: код
  комнаты и одноразовые коды должностей по отрядам. Код должности при первом
  предъявлении привязывается к `sessionId` и `epoch`, ставит `usedAt`,
  выселяет прежнюю сессию должности и пишет «должность перезашла»; вход
  завершает клик любого подтверждённого участника, не только штаба. Слово по
  рации — резерв; выбор из трёх слов только при двух и более кандидатах в
  очереди; TTL слова 5 минут от последнего использования кода. «Сменить код»
  = `epoch++`: все сессии получают 401, новый код виден только нажавшему и
  передаётся голосом в игре. Выбывший: авто-снятие через 10 минут без
  операций и «Выбыл» одним тапом по любой строке; строка гаснет через 90 с
  без heartbeat и получает «Занять»; метки снятой должности сереют в «не
  подтверждено». Интерфейс комнаты не стартует внутри iframe.
- **Ворота санкции (раздел 4).** Единственные ворота — токен администрации
  сервера, подписанный HMAC, с `keyId` в заголовке; ключ хранится в переменных
  Worker и реестровом DO, не в файле политики. Поле `server` от клиента не
  используется, форк и сервер берутся из токена; без токена комната «без
  санкции» и интерфейс скрыт. Сверки хеша политики нет: страница берёт
  `GET /policy/<fork>` как единственный источник. Отзыв — стоп-флаг в
  реестровом DO; комната перечитывает его на первом запросе, пришедшем не
  раньше чем через 60 с после прошлой проверки, и на своём alarm'е;
  `ROOMS_ENABLED=0` в дашборде — глобальный
  backstop.
- **Лимиты (разделы 3 и 7).** `INSERT ops` + `UPSERT objects` без лишних
  индексов, ≤2 строки на операцию. Лимитер по источнику входа (IP-адрес из `CF-Connecting-IP`), никогда по коду комнаты. Байтовый бюджет 2 МБ и 2000 объектов
  на комнату, сообщение до 4 КБ, снимок пачками по 200. Потолки в переменных:
  `ROOMS_MAX_CONCURRENT=6`, `ROOMS_MAX_DAILY=30` на платном плане Workers
  (решение владельца «больше сессий в день»; бесплатный тариф упирается в
  8–16 комнат в сутки). Реестровый DO ведёт счётчики и `GET /health` (только
  числа). При потолке отказывают новые комнаты текстом, активная комната не
  трогается; жёсткий отказ переводит её в «Радиомолчание»: баннер над картой
  и «данные заморожены с HH:MM» на каждой карточке.
- **Срок жизни комнаты (раздел 2).** `roomMaxSec: 10800` от создания, за 20
  минут до конца в ленте «продлить на час» один раз (предел 4 часа);
  `roomIdleLockSec: 480` — 8 минут без операций дают плашку «новый раунд?»
  одной кнопкой в ленте, не модальным окном; после блокировки операции
  запрещены, экспорт живёт `exportGraceSec: 3600`, затем alarm удаляет
  объект. Шестичасовой `roomIdleSec` отменён.
- **Шов (раздел «Архитектура»).** `view` экспортируется из IIFE
  `tactical.js` одной строкой; чужие объекты рисуются через публичный
  `view.addLayer` (`mapview.js`) с письменным контрактом «слой переживает
  смену уровня и зума» и тестом на два уровня × два зума; слот панели —
  соседний элемент вне `#tacPanel`; хук `TacRoom.attach({view, getContext,
  takeTarget})` плюс пять уведомлений `addMarker`, `finishShape`,
  `itemDelete`, `recordShot` (`fired`), `setTarget`; guard-тест ищет
  `TacRoom.attach` в трёх точках `tactical.js`. `mapview.js` не меняется.
  Запасной путь — `window.__tacView = view` и явный форк
  `drawShape`/`markTile`/`drawText` в `room.js`.
- **Экран (раздел 5).** Свой `@media (max-width: 1100px)` в `room.css`,
  правило 900 px из `tactical.css` не переиспользуется. Бюджет узкой
  раскладки: шапка 36 + чипы 28 (одна строка, горизонтальная прокрутка) +
  карта 500 + лента 64 (три карточки по 280) + панель 300 со своей
  прокруткой, подвал скрыт; узкая панель — две вкладки «Запросы» и
  «Ресурсы», реестр и слои — полка-чип «Реестр 7/12» поверх карты (полка из
  JS); цели нажатия 44 px. Карточка огня серии T монтируется внутрь
  раскрытого запроса, переключение «Огонь / Комната» остаётся только для
  личных расчётов. Read-only показывается полосой над картой с живыми
  кликами чтения; после 20 минут тишины — тихий реконнект по клику, не экран
  «сессия истекла». Под новой меткой противника подпись «не передано»,
  которую снимает одним кликом любой в комнате.
- **Реестр (раздел 4).** Должности с правами: `co`, `xo`, `so`, `ot`
  (техник вооружения — снаряды и боеголовки ОБ), `sl` и `ftl` по отрядам,
  `pilot`, `ro`, `cmo`, `observer`. Функции — ярлыки на строке, назначает
  штаб живым, без передачи, с записью в журнал, прав не дают: JTAC,
  миномётный расчёт, aSL, DCC, синтетик. Ресурсы `claimable`: участник берёт
  «Расчёт» на конкретный миномёт, `acceptRequest` действует только на него.
  Звук (владелец, 2026-09-14): расчёт, на чей ресурс нацелен запрос, слышит
  повторяющийся пинг каждые 10 с, срочный — каждые 5 с, пока запрос не
  обработан или не отмечен «Услышал» локально; автор ничего не слышит; пока
  комната заморожена (радиомолчание, рубильник администрации, бюджет),
  заблокирована или закрыта, пинг молчит и звучит снова сразу после.
- **Пакет для администрации (раздел 4).** Одно письмо: «да» и `keyId` вместе,
  после волны серии J тем же контактом. Порядок показа: страница «чего
  инструмент не делает», их рубильник и `keyId`, ссылка наблюдателя;
  архитектура не показывается. Текст исключения к правилу 3 с условиями
  (а)–(д) и три обещания — в решении. Честная оговорка: «инструмент не знает
  о смерти персонажа, снятие идёт по бездействию и рукой любого офицера».
  Если администрация не возьмёт ключ — ключ у нас, им именная ссылка
  «отключить нас».
- **Пилот (раздел 8).** Успех = опубликованный текст исключения в правилах
  Stories и ноль тикетов по правилу 3 за четыре недели. Вторичный порог
  KT-B: ≥6 полезных комнат (≥3 подтверждённые должности, ≥1 запрос до
  «выполнен», ≥10 операций от ≥3 клиентов), из них ≥3 с разными создателями
  и минимум одна без владельца в реестре; ≥5 офицеров в ≥2 раундах; медиана
  «запрос → принят» <60 с. Числа — из журнала экспорта; в Метрике четыре цели
  `room_create`, `room_confirm`, `room_request_done`, `room_export` по «ок»
  владельца. Когорта пилота — три именованных офицера пилотного сервера,
  владелец не в счёт.
- **Порядок сборки (раздел 9).** Решение владельца: серия собирается целиком,
  письмо администрации (V3) уходит параллельно; пилот на живом сервере —
  только после письменного «да». QR на бумаге, генерация кодов отдельной
  подсистемой и делегирование администрирования вырезаны из объёма.

## Интеграция

- **Параллельная работа с серией T:** V1–V4 не трогают `tactical/*` и
  `tactical.html`; шов (V5) — один коммит из трёх правок в свободное окно
  серии T, согласованное с владельцем; до шва чужие объекты не рисуются, но
  реестр, запросы и ресурсы уже работают.
- **Деплой:** новые файлы `tactical/room*.js`, `tactical/room.css`,
  `tactical/policy/*.json` — в cp-list `deploy.yml` (CI-guard ловит пропуск);
  `?v=` у `room.js` и `room.css` в `tactical.html`; `sw.js` не меняется
  (network-first). Worker: `wrangler.toml` получает `[[durable_objects.bindings]]`
  и `[[migrations]] new_sqlite_classes = ["Room"]`; деплой делает владелец
  (`npx wrangler deploy`); адрес — константа `ROOM_URL` в `room.js`, пустая
  константа прячет интерфейс комнаты, как `FEEDBACK_URL`.
- **Разделы:** карточка «Тактическая карта» получает «что нового» и новый
  скриншот при выпуске (серия H).
- **Аналитика:** цели `room_create`, `room_join`, `room_confirm`,
  `room_publish`, `room_request`, `room_request_done`, `room_asset`,
  `room_export`, `room_observe`, `room_denied` — регистрируются в реестре и на
  счётчике только по «ок» владельца.

## Решения по scope (владелец, 2026-09-13)

- Внешний веб-инструмент, полноценная версия, не прототип; Stories первыми.
- Никакого пилота на живом сервере без письменного «да» администрации.
- Вариант A: режим комнаты внутри `tactical.html`, не отдельная страница.
- Раскладка D; почерк уровней A; гладкие кривые по умолчанию, ломаная
  переключателем, протяжка мышью.
- Вход по ходу операции обязателен: «стук» при закрытой комнате, подтверждение
  одного, передача должности.
- Состояние КАС и всех ресурсов — только вручную, отсчёты как подсказки.
- Политика сервера — конфиг, не код; санкция по серверам.
- Этап 1 (2026-09-13): комната на двоих — офицер штаба и миномётный расчёт. Запросы
  на удар и на позицию, статусы, миномёт с дальностями на карте офицера. Общие метки,
  линии и зоны (V8) — во второй волне; полная политика живёт тестовой фикстурой.
  Подробности — раздел «Stage 1» плана и пункт 5 «Owner overrides» записи решения.

## Верификация

- **Логика:** `node scripts/test_room_logic.js` — слияние журнала, победа по
  `seq`, надгробия, права по политике, фильтры, срок жизни, отсчёты.
- **Worker локально:** `npx wrangler dev` (Durable Object в miniflare) и
  `node scripts/test_room_worker.mjs`: создать → войти двумя клиентами →
  подтвердить → операции → разрыв и досылка по `since` → снимок при обрезанном
  журнале → лимиты → отказ по политике → закрытие и экспорт.
- **Сквозной сценарий в превью**, две вкладки панели браузера, Worker
  локально: CO создаёт комнату; SL Bravo входит по коду и слову; CO
  подтверждает; SL ставит метку противника и запрос миномёта; расчёт
  принимает, «Взять цель», «Выстрел», статус «огонь» с отсчётом, «выполнен»;
  блокировка и «стук» третьего офицера; закрытие вкладки и возврат с
  восстановлением должности; смена кода. Скриншот каждого шага.
- **DoD инкремента:** тесты зелёные, сценарий пройден кликом, cache-bust
  выполнен, коммит.
- **DoD серии:** настоящий раунд на Stories Core с письменного «да»
  администрации: три и более подтверждённых должности, модератор открыл
  ссылку наблюдателя, экспорт получен, жалоб по правилам нет. До раунда —
  никаких публичных анонсов.

## Риски и допущения

- **Санкция.** Администрация Stories может отказать или ограничить (только
  штабные должности, такт общего слоя). Политика как конфиг переживает
  ограничения; отказ — комната остаётся выключенной, калькулятор живёт.
- **Апстрим.** PR 9194 (слои отрядов, реплей, калибровка в игре) и PR 10519
  (командный интерфейс) меняют внутриигровую сторону; Stories портирует
  командные PR раньше RMC14. Перед V5 и V6 сверяться с их состоянием.
- **Принятие.** Комната полезна при CO и нескольких SL в одном раунде; вход
  должен занимать полминуты, иначе её бросят. Порог отмены по Vision B3
  назначается до пилота.
- **Утечка кода** к игрокам за ксеносов: блокировка после брифинга, ротация,
  ссылки только для чтения, реестр с временем входа.
- **Бесплатный тариф.** Потолок комнат в сутки и лимиты операций держат
  расход в пределах Free; рост — платный план Workers.
- **Окно серии T** для шва может сдвинуться; V1–V4 от него не зависят.
- **Деплой владельцем:** `wrangler login`, `wrangler deploy`, константа
  `ROOM_URL` — три ручных шага, как у формы идей.
- **QR на бумаге** не проверен в игре: зазоры строк, лимит длины; запасной
  вариант — только код.
