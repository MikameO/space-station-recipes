# Дизайн: прайс-лист карты — «что продать» (режим таба Maps)

- **Дата:** 2026-07-27
- **Статус:** одобрено (автономная сессия: решения приняты по полному описанию задачи пользователя, с опорой на прецеденты серии E), готов к реализации
- **Затрагивает:** `ss14_map_extractor.py` (реестр цен + новый выход `maps/<fork>/prices.json`), `maps.js` (режим списка), точечно `index.html` (кнопка, cache-bust), `style.css`, `i18n.js` (словарь)
- **Серия:** S (ROADMAP)

## Проблема

Две персоны из запроса пользователя:
1. «Ищу самые дорогие предметы на карте» — охотник за ценностями (карго,
   сальважеры, антаги, вор).
2. «В принципе ищу, что можно продать» — игрок, просматривающий весь
   ассортимент станции.

Существующий таб Maps отвечает только на вопрос «где предмет X» — вход через
поиск одного предмета. Обе персоны входят с другой стороны: им нужен **общий
список предметов карты** с сортировками по названию, по числу на карте и по
стоимости. Цен в данных проекта сейчас нет вообще.

## Утверждённые решения

| Вопрос | Решение |
|---|---|
| Размещение | Режим внутри таба Maps (оверлей-панель над canvas), не отдельный таб — реиспользует выбор карты, данные и `pick()` |
| Данные цен | Новый лёгкий файл `maps/<fork>/prices.json` из реестра прототипов; **испечённые JSON карт не трогаем** (перебейк 15 форков дорог и не нужен) |
| Формула цены | Точная копия `PricingSystem.GetEstimatedPrice` из живого кода SS14 (проверено 2026-07-27): материалы × стопка + (StackPrice × стопка ⊕ StaticPrice) |
| Число на карте | Считается на фронте из уже существующих `items[pid].p`: пол/шкаф/off-grid; вероятностные слоты — как ожидаемое значение (Σ prob) |
| Вендоматы | По умолчанию исключены из счёта (товар не бесплатен, сток раздувает итог); чекбокс «с вендоматами» включает |
| Сортировки | Название / Кол-во / Цена / Итого (= кол-во × цена); дефолт — Итого по убыванию (персона №1 получает ответ нулевым кликом) |
| Клик по строке | Закрывает панель и вызывает существующий `pick(pid)` — маркеры + список локаций |

## Данные и пайплайн

### Семантика цен (сверено с живым кодом, не по памяти)

Источник: `Content.Server/Cargo/Systems/PricingSystem.cs` (space-wizards
master, fetch 2026-07-27) + живые YAML в `cache_maps/vanilla`:

- `StaticPrice.price` — плоская цена (`- type: StaticPrice / price: 2500`).
- `StackPrice.price × count` — цена за единицу стопки; **взаимоисключающа
  со StaticPrice** (движок: если стопочная цена применилась, статическая
  не добавляется).
- Материалы: `PhysicalComposition.materialComposition` → `Σ(цена материала ×
  количество)`, затем `× count` стопки. Цены материалов — прототипы
  `type: material` (`Resources/Prototypes/Reagents/Materials/materials.yml`,
  `price: 0.35` = цена за единицу). Именно так ценятся золото/серебро/плазма —
  топ ответа для персоны №1; без этого слоя слитки стоили бы 0.
- Размер стопки: явный `Stack.count` в цепочке наследования, иначе дефолт C#
  `Count = 30` (проверено в `StackComponent.cs`), обрезанный `maxCount` типа
  стопки (`type: stack` прототипы, own-наследование через `parent`).
  Пример: `IngotGold` (Full) → count = min(30, maxCount=10) = 10.
- Всё считается по цепочке `parent` — реестр экстрактора уже хранит все
  компоненты каждого прототипа, добавляются только методы.

### Выход

`maps/<fork>/prices.json`:

```json
{"schemaVersion": 1, "fork": "vanilla", "prices": {"IngotGold1": 60, "Crowbar": 20}}
```

- Цены — за один экземпляр *как заспавнен* (полная стопка для Full-вариантов).
- Нулевые/отрицательные цены опускаются (отсутствие ключа = 0).
- Прототипы: те же виды, что попадают в предметный индекс карт
  (item/mach/container/vendor) — механизмы и шкафы тоже имеют цены.
- Генерация не требует парса карт: только реестр прототипов → новый флаг
  CLI `--prices` пишет prices.json и пропускает бейк PNG/JSON.
  `process_fork` без флага тоже пишет prices.json (обычный regen обновляет
  цены автоматически).
- Деплой: `deploy.yml` копирует `maps/` целиком — новые файлы едут в прод
  без правки workflow (урок «whitelist» учтён).

### Ограничение кэша

`cache_maps/` содержит прототипы 7 форков; для остальных 8 форков с картами
(carpmosia, deadspace, deltav, frontier, funky, goob, rmc14, rucm) генерация
цен потянет обычный сетевой fetch дерева прототипов (как при E4) — S3
запускается фоном и устойчив к отказам (форк без данных просто пропускается,
фронт деградирует изящно).

## Фронтенд (maps.js)

- Кнопка `$ Sell list` в тулбаре (активна после загрузки карты) →
  оверлей-панель поверх canvas-области.
- Панель: заголовок (фильтр-инпут по подстроке имени/ID, чекбокс
  «с вендоматами», ×), таблица `Предмет | Кол-во | Цена | Итого`,
  клик по заголовку — сортировка asc/desc (стрелка — отдельный `<span>`,
  чтобы не ломать текстовый ключ i18n-словаря).
- Кол-во: пол/off-grid = 1; шкаф: `p[4]<1` → +prob (ожидаемое, отображается
  `≈N.N`), `p[4]≥1` → +amount; вендомат — только при чекбоксе.
- Итого = кол-во × цена, `toLocaleString`, сортировка дефолтом по нему desc.
- `prices.json` грузится лениво раз на форк (кэш в состоянии таба);
  404/сеть → список живёт без колонок цен, плашка «нет данных о ценах».
- Метрика: goal `maps_sell_list` при открытии панели (прецедент E-серии).
- Cache-bust: bump `?v=` у maps.js, style.css, i18n.js в index.html.

## Обработка ошибок

- Экстрактор: материал/тип стопки не найден → вклад 0, warning-счётчик;
  regen не падает. Счётчики «прототипов с ценой / всего» в вывод.
- Фронт: отсутствие prices.json — не ошибка (форк без данных), таблица
  работает по кол-ву; повторный вход не рефетчит после успеха.

## Верификация (DoD)

- Selfcheck экстрактора (вживую против YAML): `Crowbar` — цена статическая
  и совпадает с YAML; `IngotGold1` = 100 × цена материала Gold × 1; полный
  `IngotGold` = ×10; `SheetSteel` = 30 × Σ(состав × цена материала);
  у прототипа со StackPrice статическая цена НЕ прибавлена.
- Ручной спот-чек 3 прототипов по живым файлам кэша.
- Фронт e2e в preview (eval-клики по памяти проекта: preview_click сломан):
  таб Maps → карта → `$ Sell list` → дефолтная сортировка по Итого,
  топ-строка правдоподобна; клик по строке → маркеры; сортировка по имени
  и по числу; чекбокс вендоматов меняет счёт; скриншот-доказательство.
- RU-режим: заголовки/кнопка переведены (словарь i18n).

## Не-цели (YAGNI)

- Цены растворов (`pricePerUnit` реагентов × объём) — реальная механика,
  но мелкие суммы и риск двойного счёта (слитки несут Solution-компонент);
  кандидат в отдельный инкремент.
- `MobPrice` — мобов в предметном индексе карт нет вообще.
- `RandomPrice`, per-instance переопределения `Stack.count` на карте —
  редкость; цена «как в прототипе» честно документируется.
- Deep-link на открытую панель (`list=1`) — не в v1.
- Глобальный режим «самый дорогой предмет по всем картам» — v2, требует
  общий индекс.

## План реализации (серия S)

1. **S1 — данные:** реестр цен в `ss14_map_extractor.py` (материалы, типы
   стопок, `price()`), выход prices.json, `--prices`, selfcheck-asserts,
   генерация vanilla из кэша (офлайн). Спот-чек вручную.
2. **S2 — фронт:** режим списка в maps.js + кнопка/стили/i18n, e2e в preview
   со скриншотом, cache-bust.
3. **S3 — раскатка и докы:** prices.json для всех 15 map-форков (сетевой
   fetch 8 некэшированных), sanity-счётчики, README-строка фичи, CHANGELOG,
   ROADMAP серия S + ревизия.
