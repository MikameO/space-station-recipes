# Командный планшет — этап 2а: позиции, зона миномёта, адресные запросы, общая привязка

**Статус:** решения владельца приняты в чате 2026-09-14 (ответы на вопросы и «Делай дальше сам целиком»). Цель — полевой тест вечером 2026-09-14 на продакшн-версии сайта с миномётным расчётом и, возможно, вторым офицером. Комната остаётся скрытой для всех (`ROOM_URL` пустой, санкция `none`); тестеры включают её у себя dev-флагом.

Основа: спека серии V [2026-09-13-tactical-tablet.md](2026-09-13-tactical-tablet.md), запись решений [../decisions/2026-09-13_tactical-tablet.md](../decisions/2026-09-13_tactical-tablet.md), этап 1 в плане [../superpowers/plans/2026-09-13-tactical-tablet.md](../superpowers/plans/2026-09-13-tactical-tablet.md).

## 1. Решения владельца

| Вопрос | Решение |
|---|---|
| Кто может быть адресатом запроса | любая должность или конкретный участник |
| Кто передаёт позицию | любой подтверждённый участник; у миномётного расчёта та же кнопка ставит и его миномёт |
| Общая привязка | одна привязка комнаты, свежая заменяет прежнюю; у каждого «Применить у себя / Уточнить своим замером и опубликовать / Оставить свою»; в реестре видно, кто по какой работает |
| Типы запросов для не-миномёта | новый тип «Задача» (`task`); «Позиция» — любой должности; «Удар миномёта» — только расчёту |
| Подход | рекомендованные варианты во всех частях (позиция — поле участника; адресат — поле `to`; привязка — объект `calibration` с тайлом и показанием; зона — кольцо дальности; калибровка сворачивается) |
| Процесс | делать целиком самостоятельно до прода; war-room по изменению контракта заменён финальным адверсариальным ревью (срок — вечер того же дня) |

## 2. Контракт (tactical/room-logic.js — общий для страницы и Worker)

### 2.1 Участник (`member`)

Объект участника пишет только он сам (`existing.client === actor.client`), только `patch`.

- `presentAt` — как в этапе 1, пульс присутствия; сервер ставит `presentAt = now`.
- `pos` — `null` или `{x, y, level?}`: `x`, `y` — целые координаты мира (|v| ≤ 4096), `level` — целое. `null` убирает позицию. Сервер ставит `posAt = now` при любой записи `pos`.
- `cal` — `null` или `[dx, dy]` из целых (|v| ≤ 4096): каким сдвигом калибровки пользуется участник; `null` — калибровки нет.
- Разрешённые ключи: непустое подмножество `presentAt`, `pos`, `cal`; иное — `fields`; неверная форма — `pos` или `cal`.
- Уровень `observer` не пишет `pos` и `cal` (`level`).
- **Пульс.** Пакет, где каждая операция — `patch` участника с единственным ключом `presentAt`, по-прежнему проходит блокировку простоя и радиомолчание. Запись с `pos` или `cal` — обычная: при радиомолчании, блокировке, остановке и закрытии — 423 с соответствующей причиной.
- Новые функции логики: `validateMemberPatch(policy, member, data)` → код ошибки или `null`; `isHeartbeat(op)`.

### 2.2 Запрос (`request`)

- `to` — необязательное поле, только при создании (`put`), в `patch` не разрешено:
  - `{post}` — должность из политики, уровень не `observer`;
  - `{post, squad}` — то же, отряд есть в `policy.squads`;
  - `{client}` — строка 1–64 символа.
  Иные ключи или неверные значения — `to`. `cleanData` пересобирает `to` только из разрешённых ключей.
- Тип `task` («Задача»): добавлен в `REQUEST_TYPES`, ресурса нет. `to` обязателен (иначе `to`), `note` обязателен и не пуст (иначе `note`), `target` необязателен (если есть — проверяется как раньше). Для всех прочих типов `target` обязателен, как раньше.
- «Удар миномёта» (`mortar`) с `to.post` принимает только должность-владельца миномёта (`assetOwnerPost(policy, 'mortar')`), иначе `to`. `to.client` для `mortar` и `position` разрешён (проверку, что это участник расчёта, делает интерфейс).
- `isAddressee(req, member)`: `to.client === member.client` или (`to.post === member.post` и (нет `to.squad` или `to.squad === member.squad`)).
- Право `acceptRequest` для запроса с `to`: уровень из списка права (штаб) **или** адресат; правило `asset-owner` и закреплённые расчёты для такого запроса не действуют. Без `to` — как в этапе 1.
- `requestActions` для `task`: `requested` → `accept`, `deny` (адресат или штаб), `cancel` (автор); `accepted` → `done`, `deny` (адресат или штаб), `cancel` (автор); `done`/`denied` → `repeat` (автор). `fire`, `take`, `place`, `load` для `task` не предлагаются. Автор никогда не принимает свой запрос (как в этапе 1).
- Создают запросы, как раньше, должности с правом записи в слой `requests` (Stories: штаб и служба).

### 2.3 Привязка комнаты (`calibration`)

- Разрешённые поля: `offset` (как раньше), `tile` `[x, y]` и `reading` `[gx, gy]` — целые, оба или ни одного; если есть, `offset` должен равняться `reading − tile` (иначе `offset`).
- Запись (`put`, id `calibration`) заменяет прежнюю; публикуют должности с правом `publishCalibration` (Stories: штаб и служба). Автор и время — служебные `by`/`at`.

### 2.4 Журнал модератора (worker/room/export.js)

- `запрос №N «задача» → миномётный расчёт: <текст>`; у прочих типов с адресатом — `→ <адресат>` после координат. Адресат: название должности (с отрядом) или позывной и должность участника.
- `позиция: <участник> <x> <y> (мир)`; при известной привязке комнаты — игровые числа.
- `позиция снята: <участник>` для `pos: null`.
- `привязка комнаты: <участник>, сдвиг +dx −dy` (показание дальномера и тайл, если есть).
- Записи `cal` в журнал не попадают.

## 3. Интерфейс

### 3.1 «Передать позицию» (tactical/room-requests.js)

- Кнопка в строке инструментов у каждого подтверждённого участника: включает выбор тайла на карте (`consumePick`), калибровка не нужна.
- Если в панели огня стоит свой миномёт (`getContext().mortar`), рядом кнопка «Позиция из панели огня».
- Отправка: `patch member {pos: {x, y, level}}`; у участника, который владеет миномётом по должности или закрепил его, тем же пакетом — `patch asset {tile, state: 'deployed'}` для его миномёта (при нескольких — закреплённый за ним, иначе первый его должности).
- «Убрать позицию» — `pos: null`.
- При радиомолчании — уведомление из ответа 423 (как для прочих записей).

### 3.2 Карта командования (слой комнаты)

- Метки участников с `pos` на планете комнаты и текущем уровне: ромб цвета уровня (`levelStyle`), подпись «Позывной · N мин» (без позывного — название должности). Старше 5 минут — полупрозрачная. Метки удалённых участников не рисуются.
- Каждый развёрнутый миномёт с тайлом: полупрозрачное зелёное кольцо между `minRange` и `maxRange` (заливка кольца), красная полупрозрачная заливка внутри `minRange`, контурные линии обоих радиусов, подпись «Миномёт N · позывной расчёта» у квадрата миномёта.
- Флажок «Зона миномётов» во вкладке «Ресурсы» (по умолчанию включён, хранится в `room-prefs.zone`) скрывает кольца и заливки, квадрат миномёта остаётся.
- Красный слой местности «куда миномёт не бьёт» остаётся слоем панели огня и виден под комнатой при оружии «Миномёт».

### 3.3 Адресные запросы и «Задача» (tactical/room-requests.js)

- Тип «3 Задача» в строке типов.
- Список «Кому»: «Всем по типу» (у «Задачи» не показывается), затем должности (без наблюдателя; с отрядами, если они есть в политике), затем подтверждённые участники «позывной · должность» кроме себя. Для «Удара миномёта» — только должность-владелец миномёта и её участники.
- «Задача»: поле «Текст задачи» обязательно (лимит `note`), «Указать на карте» необязательно; без точки карточка показывает «без точки».
- Карточка: после типа — «→ адресат». Кнопки действий берутся из `requestActions` (адресат и штаб). Пинг звучит только у адресата запроса с `to`; без `to` — как в этапе 1.
- Запрос без точки не рисуется на карте и не даёт «Взять цель».

### 3.4 Общая привязка (tactical/room-ui.js)

- Плашка наверху панели комнаты, если привязка комнаты есть и отличается от вашей (`getContext().calibration.offset`) или своей нет: «Привязка комнаты: <позывной> (<должность>), HH:MM, сдвиг +dx −dy» и кнопки «Применить у себя» (только если у привязки есть `tile` и `reading`) и «Оставить свою». «Оставить свою» прячет плашку до смены привязки комнаты (sessionStorage по `at` привязки).
- «Применить у себя» вызывает хук `applyCalibration({tile, reading, offset})`; при успехе — уведомление «Привязка комнаты применена».
- «Опубликовать мою привязку» в строке инструментов у должностей с правом `publishCalibration`, если своя калибровка есть и отличается от комнаты (или в комнате её нет): `put calibration {offset, tile, reading}`. Подпись кнопки поясняет «уточнить своим замером».
- Реестр: у подтверждённых участников метка «✓ привязка комнаты» (`cal` совпадает с привязкой комнаты), «своя привязка» (`cal` иной), «нет привязки» (`cal: null`); без поля `cal` — ничего. У участника с `pos` — «позиция 30 −90 · N мин».
- Синхронизация `cal`: раз в тик клиент сравнивает свою калибровку с последней отправленной и шлёт `patch member {cal}` при изменении (после отказа 423 — повтор на следующем тике после снятия заморозки).

### 3.5 Панель огня (tactical/tactical.js)

- Хук `applyCalibration(cal)` в `TacRoom.attach`: проверяет форму (`tile`, `reading` — целые пары, `offset = reading − tile`) и наличие планеты; ставит калибровку как после «Сохранить сдвиг раунда» (`tile`, `reading`, `offset`, `at`, проверочный тайл через `Logic.pickCheckTile`), подтверждает тот же раунд, сохраняет и перерисовывает; возвращает `true`/`false`.
- Сворачивание: `Logic.calCollapsible(calibration, calState, variance)` — `true`, когда калибровка есть, проверочный тайл подтверждён или его нет, сдвиг в допуске и нет вопроса «тот же раунд?». Тогда блок калибровки — строка «Привязка: сдвиг +dx −dy · N мин · ✓ проверено» (без проверочного тайла — без «✓ проверено») с кнопкой «Изменить»; раскрытый блок при `calCollapsible` получает кнопку «Свернуть». Раскрытие — только в памяти страницы; «Новый раунд» и «Откалибровать заново» сбрасывают его.
- `renderPanel` по-прежнему ничего не знает о комнате.

## 5. Выкатка

- Дорожки в отдельных worktree: **T** (панель огня), **W** (Worker, журнал, фикстура, сверка), **R1** (запросы, позиция, зона), **R2** (панель комнаты, привязка, реестр). Контракт `room-logic.js` делает координатор в main до слияния дорожек.
- Слияние: логика → W → T → R2 → R1; все наборы тестов; сквозная проверка; финальное адверсариальное ревью (права `to`, пульс, привязка, XSS в подписях и адресатах).
- Cache-bust в `tactical.html` одним коммитом при интеграции (`room-logic.js`, `room-ui.js`, `room-requests.js`, `room.css`, `tactical.js`, `tactical.css`, при изменении — `room.js`, `logic.js`).
- Push, проверка Pages, `wrangler deploy`, смоук прода (health, policy, создание комнаты ключом `stories-k1`, позиция и задача через HTTP).
- Тестеры включают комнату на `https://mikameo.github.io/space-station-recipes/tactical.html` строкой в консоли: `localStorage.setItem('chemdb-tactical:room-dev', JSON.stringify({url: 'https://chemdb-feedback.chemdb-feedback-worker.workers.dev'}))`. Создателю нужен ключ `stories-k1`; остальные входят по коду с листа брифинга.
- Правило 3 Space Stories: игра в живом раунде с комнатой без письменного «да» администрации — решение владельца; публичное включение (`ROOM_URL`, статус `pilot`) не делается.
