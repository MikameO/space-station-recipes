## Проблема

Игроки пишут внутриигровые документы: уставы, доктрины, памятки ролей. Они
живут на листе бумаги внутри раунда и исчезают вместе с ним; чтобы выдать
документ снова, нужен его исходник в разметке бумаги SS14. Платформа состоит
из инструментов-вкладок и не имеет места для длинного текста.

Нужен архив, который:

1. хранит текст **дословно** как исходник разметки бумаги (тексты чужие,
   правки в них не вносятся);
2. показывает документ так, как его видит игрок на бумаге;
3. позволяет скопировать разметку и заново выдать документ в игре, не превысив
   лимит бумаги;
4. растёт добавлением файла и одной записи в манифест — без правок кода.

## Что делает страница

1. **Список документов**, сгруппированный по ролям, с бейджем форка.
2. **Просмотр документа** как лист бумаги: светлый фон, цвета, жирный, курсив,
   заголовки — как в игре.
3. **Вкладка «Markup»**: исходник в `<pre>`, кнопка «Copy markup», счётчик
   длины вида `9549 / 10000 characters` (файл хранит завершающий перевод
   строки, он в счёт и в буфер обмена не попадает). Лимит 10000 — поле `ContentSize`
   в `Content.Shared/Paper/PaperComponent.cs`; на 2026-09-11 одинаков
   в `space-wizards/space-station-14` и `RMC-14/RMC-14` (проверено по raw
   GitHub). Сервер сверяет длину **строки вместе с тегами** (`string.Length`,
   UTF-16 code units). YAML-переопределения RuCM не проверялись.
4. **Deep link** `library.html#doc=<id>`; список меняет хэш, хэш выбирает документ.
5. **RU/EN шапка** через существующий `i18n.js`; тексты документов остаются
   на языке оригинала.

Чего нет намеренно (YAGNI): поиска, оглавления, per-doc HTML-страниц,
редактора. Появятся при пяти и более документах (см. Backlog серии).

## Данные: манифест и файлы документов

`library/index.json`:

```json
{
  "schemaVersion": 1,
  "documents": [
    {
      "id": "rucm-staff-officer-doctrine",
      "title": "Доктрина оперативного управления и штабной работы",
      "role": { "en": "Staff Officer", "ru": "Офицер Штаба" },
      "fork": "rucm",
      "forkName": "Russian Marine Corps",
      "lang": "ru",
      "kind": "paper",
      "file": "rucm-staff-officer-doctrine.paper.txt",
      "author": "Штаб роты, RuCM",
      "provenance": "Выдан командующим роты во время раунда за Офицера Штаба. Текст воспроизведён дословно.",
      "received": "2026-09-10",
      "notes": ""
    }
  ]
}
```

Правила:

- `id` — slug `<форк>-<роль>-<суть>`, латиница, дефисы; `file` = `<id>.paper.txt`.
- `title`, `author`, `provenance`, `notes` — строки на языке документа;
  `role` — двуязычный объект, страница берёт `role[lang]`.
- `forkName` хранится в манифесте, чтобы страница не грузила 3 МБ `data.json`
  ради одного имени; значение совпадает с `FORK_REGISTRY[fork]["name"]` в `config.py`.
- Файл документа — UTF-8 без BOM, переносы LF, текст **без правок**.
  Редакторские замечания (например, три нестыковки доктрины: формула
  Ланчестера против правила «4 к 1», дыры в диапазонах СС, правило дистанции
  «A + B = C + D») живут только в `notes`, и в первой версии поле пустое —
  по решению пользователя документ публикуется как есть.
- Длина текста не хранится, страница считает её при загрузке.

## Рендерер разметки

Собственный, без библиотек, как весь фронтенд проекта (ни одной сторонней
JS-зависимости с коммита A1.1).

- **Вход:** сырой текст. Сначала экранируются `& < > "`, затем токенизатор
  ищет теги регуляркой `\[(\/)?([a-z]+)(?:=([^\]]*))?\]`.
- **Теги** (набор Robust Toolbox `Robust.Client/UserInterface/RichText`):

  | Тег | Вывод | Условие |
  |---|---|---|
  | `[color=X]…[/color]` | `<span style="color:X">` | X — `#hex` (3/6/8 знаков) или имя из букв; иначе тег остаётся текстом |
  | `[bold]` | `<span class="lib-b">` | |
  | `[italic]` | `<span class="lib-i">` | |
  | `[bolditalic]` | `<span class="lib-bi">` | |
  | `[head=N]` | `<span class="lib-h1|h2|h3">` | N ∈ 1..3, без аргумента = 1; строчный span, а не блочный `<h*>`, потому что заголовок бумаги не рвёт строку |
  | `[bullet]` | `• ` | самозакрывающийся |
  | `[mono]` | `<span class="lib-mono">` | |
  | `[font=…]` | прозрачный span | аргумент игнорируется |
  | прочее | видимый текст тега | как есть |

- **Вложенность:** стек открытых тегов. Закрывающий тег вида K: если K нет
  в стеке — остаётся текстом; иначе спаны выше K закрываются, K закрывается,
  затем закрытые спаны открываются заново в прежнем порядке. Это даёт валидный
  HTML на перепутанном порядке закрытия — в доктрине строка
  `[color=#AAAAAA][italic] … [/color][/italic]` именно такая.
- **Пробелы и переносы** сохраняются (`white-space: pre-wrap;
  overflow-wrap: anywhere`), поэтому центрирование строк пробелами и шапка из
  блочных символов `█▀▄░` выглядят как в игре.
- **Лист** `.lib-sheet`: фон `#efe9db`, текст `#1e1e1e`, шрифт
  `'Noto Sans', 'Segoe UI', sans-serif`, 15 px, межстрочный 1.45,
  максимум ~760 px. Белые блоки `[color=#ffffff]` на светлом листе почти
  невидимы — так и в игре, это не дефект.

## Страница и её разметка

`library.html` — самостоятельная страница на том же `style.css`
(шрифты приходят через его `@import`), с тем же счётчиком Метрики.

- **`<head>`:** `<title>Library — NanoTrasen ChemDB</title>`, description,
  `og:*` с тем же `og-image.png`, canonical
  `https://mikameo.github.io/space-station-recipes/library.html`, `lang="en"`
  (i18n.js переключит на ru).
- **Шапка:** `.header-left` — логотип-ссылка на `./` и название Library;
  `.header-right` — `#langToggle` (i18n.js вешает обработчик сам) и кнопка
  обратной связи на GitHub Issues. Поиска, Antag, Share и PiP нет.
- **Подзаголовок:** «In-game documents: doctrines, field manuals, role memos.
  Texts are stored verbatim.»
- **Тело:** `<main class="lib-layout">` → `<nav class="lib-list" id="libList">`
  (группы по `role[lang]`, внутри кнопки-документы с `aria-current="true"` у
  открытого, бейдж `forkName`) и `<article class="lib-doc">`:
  - `#libTitle`, строка метаданных `#libMeta` (Role · Fork · Received · Author ·
    Source);
  - переключатель видов: две кнопки `#libViewRendered`, `#libViewMarkup`
    с `aria-pressed`;
  - `#libSheet` (рендер) и `#libMarkup` (`<pre>` с исходником), виден один;
  - панель `#libCount` (`N / 10000 characters`, при N > 10000 класс
    `lib-over` и красный цвет) и кнопка `#libCopy`;
  - `#libStatus` для сообщений (`aria-live="polite"`).
- **Поведение `library.js`** (IIFE, `'use strict'`, без зависимостей):
  1. `fetch('library/index.json')` → список; ошибка → `#libStatus`
     «Failed to load the library» и кнопка Retry.
  2. Выбор документа: `#doc=` из хэша, иначе первый. Неизвестный id → первый.
     `hashchange` перевыбирает. Клик по списку пишет `location.hash`.
  3. `fetch('library/<file>')` → текст → рендер в `#libSheet`, исходник
     в `#libMarkup`, счётчик; `track('library_doc_open', {doc:id})`.
  4. Copy: `navigator.clipboard.writeText(raw)`; при отказе — выделить
     содержимое `<pre>` и `document.execCommand('copy')`; статус «Copied» или
     «Copy failed — select the text and press Ctrl+C»;
     `track('library_copy_markup', {doc:id})`.
  5. `track()` — локальная копия трёхстрочной функции из `app.js`
     (`ym(108585248, 'reachGoal', …)` в try/catch).
- **Мобиль (< 700 px):** одна колонка, список сверху, лист без
  горизонтального скролла (длинные строки переносятся).
- **Доступность:** список — `<nav aria-label="Documents">` с `<button>`;
  переключатель видов — `aria-pressed`; лист — `<article>`; фокус-стили
  наследуются от `style.css`.
- **i18n:** новые ключи в словаре `i18n.js`: `Library` → `Библиотека`,
  `In-game documents: doctrines, field manuals, role memos. Texts are stored verbatim.`,
  `Documents` → `Документы`, `Rendered` → `Как в игре`, `Markup` → `Разметка`,
  `Copy markup` → `Скопировать разметку`, `Copied` → `Скопировано`,
  `Copy failed — select the text and press Ctrl+C`, `characters` → `символов`,
  `Role` → `Роль`, `Fork` → `Форк`, `Received` → `Получен`, `Author` → `Автор`,
  `Source` → `Источник`, `Failed to load the library` → `Библиотека не загрузилась`,
  `Retry` → `Повторить`, `Back to ChemDB` → `Назад в ChemDB`.

## Ссылка из приложения

В `index.html` после кнопки Fork Diff и перед скрытой кнопкой Antag:
`<a class="tab-link" href="library.html">Library</a>`. Класс **не** `tab-btn`:
`setupTabs()` в `app.js` вешает обработчик на все `.tab-btn` и читает
`dataset.tab`, для ссылки это дало бы `getElementById('tab-undefined')`.
В `style.css` базовые правила `.tab-btn` расширяются селектором
`.tab-btn, .tab-link` (шрифт, отступы, цвет, hover); активного состояния
у ссылки нет. Whitelist табов и восстановление сессии в `app.js` не меняются.

## Деплой, офлайн, SEO

- **`deploy.yml`:** `library.html library.js` в первую строку `cp`,
  `cp -r library _site/library`. Проверочный скрипт «Verify every referenced
  asset shipped» сканирует `index.html` **и** `library.html` — забытый файл
  валит сборку, а не молча ломает страницу (уроки 2c062f6 / 3408bcd / ordnance.js).
- **`sw.js`:** в `PRECACHE` — `./library.html`, `./library.js?v=1`,
  `./library/index.json`; файлы документов не прекэшируются (сетевой
  обработчик кладёт их в кэш при первом просмотре, как карты). `CACHE`
  `chemdb-v80` → `chemdb-v81`.
- **Cache-bust:** `style.css?v=59` → `60`, `i18n.js?v=29` → `30` в обеих
  страницах и в `PRECACHE`.
- **`sitemap.xml`:** запись `library.html`, `lastmod` 2026-09-11,
  `changefreq monthly`, `priority 0.6`.
- **`NOTICES`:** новый раздел «Community-authored in-game documents (library/)»:
  тексты написаны игроками, публикуются как архив без изменений, по просьбе
  автора снимаются через GitHub Issues.

## Риски и допущения

- **Ширина листа.** В игре ширина бумаги и шрифт другие; центрирование
  пробелами и шапка из блочных символов могут лечь чуть иначе. Принимается:
  цель — читаемость и дословность, а не пиксельная копия.
- **Перепутанные теги.** Робастовский парсер и наш рендерер могут по-разному
  трактовать перепутанный порядок закрытия. Наш даёт валидный HTML и
  сохраняет оба стиля до фактического закрытия каждого.
- **Чужой контент.** Автор документа не назван. Подпись «Штаб роты, RuCM»,
  раздел в NOTICES и канал снятия через Issues. Если ник станет известен —
  правится одно поле манифеста.
- **Лимит бумаги RuCM.** Проверен только код space-wizards и RMC-14; если
  RuCM переопределяет `contentSize` в YAML, счётчик покажет неверный предел.
  Лечится полем `limit` в манифесте при первом же расхождении.
