# U2 — Accessibility / WCAG 2.1 AA audit (Round 1)

Agent: U2 (UX/UI department). Level: Claude Browser pane (CDP) against `http://localhost:64306/` (identical files to prod), viewport 1366x900 unless stated. Repo: `D:/Space Station Recipes` @ e777079.

## Design decision recorded (not a defect)
The app ships **one dark "CRT terminal" theme only** — `:root` in `D:/Space Station Recipes/style.css:15-48` defines a single palette, there is no `prefers-color-scheme` block and no theme switch. Judged on its own merits below. The theme is mostly high-contrast (body text 15.4:1, phosphor green on hull 14.3:1); the failures are concentrated in two "muted" tokens (`--text-ghost #6b7a93`, `--phosphor-dim #1a7a42`) that are used for *text*, not just for borders.

## Harness limitations that shaped the evidence
1. `computer key Enter` / `space` reach the page but arrive with **keyCode 0** (verified with a capture listener: `keydown:Enter::btn-medbay:trusted=true` and **no** `click` event). Chrome therefore does not synthesise default button activation. Native `<button>` activation by Enter/Space is guaranteed by the browser, so those cases are recorded as OK by construction (`code_verified`), and app-level `keydown` handlers (which do fire) were tested normally.
2. CSS transitions do not tick in this pane (`document.timeline` advances, but `getAnimations()[0].startTime === null`, `currentTime === 0` forever). Anything whose end state depends on a transition could not be observed — see U2-055.

PAGE / FLOW: whole app / keyboard entry
CLASSIFICATION: MISSING | SEVERITY: major | PRIORITY: P1 | CONFIDENCE: HIGH | EVIDENCE_TYPE: runtime_verified
WCAG: 2.4.1 Bypass Blocks (A)
DESCRIPTION: There is no skip-to-content link, and the sidebar filter panel precedes the main tab navigation in the DOM.
EXPECTED: A visible-on-focus "Skip to content" link as the first tab stop, or the main tablist early in the tab order.

A keyboard user must traverse the whole filter sidebar on every page load to change tab.
EVIDENCE: Tab-by-Tab `document.activeElement` trace. Programmatic tabbable order (154 elements) puts `button#btn-reagents.tab-btn` at index 62, after `input [wrapLabel:Toxins]` at index 61. Measured stops: `after+28 → button#btn-medbay.tab-btn`.
RECOMMENDATION: `index.html` — add `<a class="skip-link" href="#tab-reagents">Skip to content</a>` as the first child of `<body>` plus a `.skip-link{position:absolute;left:-9999px}` / `:focus{left:8px;top:8px}` rule in `style.css`; the tab panels already carry `tabindex="-1"` so they can receive focus.

FINDING_ID: U2-002
PAGE / FLOW: Calculator (target, Batch planner, Beaker Simulator, What Can I Make?), Craft Trees (target) / reagent autocomplete
CLASSIFICATION: BROKEN | SEVERITY: critical | PRIORITY: P0 | CONFIDENCE: HIGH | EVIDENCE_TYPE: runtime_verified + code_verified
WCAG: 2.1.1 Keyboard (A), 4.1.2 Name/Role/Value (A)
DESCRIPTION: The shared autocomplete renders suggestions as non-focusable `<div>`s wired only to `click`. There is no combobox semantics and no keyboard selection, and every downstream action is gated on an id that only the click handler can set. The Calculator and Craft Trees are therefore completely unusable with a keyboard.
EXPECTED: ArrowDown/ArrowUp move through options, Enter selects, Escape closes; `role="combobox"` + `aria-expanded` + `aria-controls` on the input, `role="listbox"`/`role="option"` on the list, `aria-activedescendant` tracking.
ACTUAL: Typed "bicaridine" into `#calcTarget` → 8 `.suggestion-item` divs, **all `tabIndex: -1`**; `#calcTarget` has `role=null`, `aria-expanded=null`, `aria-autocomplete=null`, `aria-activedescendant=null`. ArrowDown does nothing (activeElement unchanged, no highlighted item). Tab moves focus to the scroll container `#calcSuggestions` itself, not to an option. `app.js:1972` `if (!selectedCalcId) return;` — `selectedCalcId` (app.js:1965) is assigned only inside the click-driven `onSelect`, so pressing Calculate after typing the exact full name does nothing. Same gate for `currentTreeReagentId` (app.js:1894), `pendingId` (app.js:2429/2434), the Beaker Simulator (app.js:1485) and the reverse lookup.
EVIDENCE: `app.js:2095-2157` `setupAutocomplete` — the only listeners are `input.addEventListener('input', …)` and `item.addEventListener('click', …)`; no keydown anywhere. Contrast with `maps.js:175-180`, where the map item search *does* implement Enter-to-pick.
RECOMMENDATION: `app.js:2095` — add keyboard handling to `setupAutocomplete`: maintain an active index, handle ArrowDown/ArrowUp/Enter/Escape/Home/End on the input, give items `role="option"`/`id`, set `aria-activedescendant` on the input, and mark the input `role="combobox" aria-expanded aria-controls`. Cheapest interim mitigation: on Enter, select the first match (mirroring `maps.js:176`).
