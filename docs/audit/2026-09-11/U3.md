FINDING_ID: U3-001
PAGE / FLOW: production 404 route (`/does-not-exist`) vs local
CLASSIFICATION: MISSING · SEVERITY: minor · PRIORITY: P3 · CONFIDENCE: HIGH · EVIDENCE_TYPE: http_fetch_only + runtime_verified (local)
DESCRIPTION: No custom 404 page. GitHub Pages serves its generic "Page not found · GitHub Pages" page (unbranded, no link back to the app, its own CSP `default-src 'none'`). Locally python's "Error response / Error code: 404" is shown — so local testing never shows what a real visitor sees.
EXPECTED: branded 404 with a link to `./` and the search.
ACTUAL: curl → `HTTP 404 size=9379 type=text/html` title "Page not found · GitHub Pages", `links: []` on the local variant; console `[error] Failed to load resource: 404` (the only 404 of the whole session).
EVIDENCE: curl output; browser get_page_text of `/nope.html?fresh=u3a003`. sw.js:62-72 passes non-ok responses through unchanged, so the service worker cannot rescue a 404 (only network failures fall back to index.html at sw.js:73-79).
RECOMMENDATION: add a root `404.html` (GitHub Pages picks it up automatically) with the header/logo and a "Back to ChemDB" link, and add it to the cp list in `.github/workflows/deploy.yml:29-30` (the CI guard only checks assets referenced from index.html).
