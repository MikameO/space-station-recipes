# Insight: использование фич по событиям Метрики — 2026-07-28 → 2026-09-12 (чекпойнт-3)

**Источник:** счётчик 108585248. Рейтинг событий (§1) построен по сырым хитам Logs API (`logs/hits_*.tsv`, до 2026-09-11 включительно): каждый `reachGoal` лежит там как хит с URL `goal://mikameo.github.io/<event>` **независимо от того, существовала ли цель**. Остальные разделы — Reporting API ([reports/cp3/](reports/cp3/), [reports/events/](reports/events/)) и дерево параметров визитов.
**Окно:** 2026-07-28 → 2026-09-12 (47 дней). Reporting API: 1068 визитов / 292 юзера. Органика: 1019 визитов / 266 юзеров.
**Поправка на дев-шум:** исключены 7 clientID — владелец (`…438036`: 104 визита с 2026-04-17, Yandex Browser, Долгопрудный/Кострома) и клиенты со служебными URL (`?nocache=`, `?fresh=audit-orch`, `?cb=`, `?prodcheck`, `localhost`). Хиты с `localhost`/`127.0.0.1`/`file://` (preview-сессии) в Logs API присутствуют, но их визиты вырезаны фильтром счётчика «только зеркала» — поэтому в §1 учтены только clientID, у которых есть хотя бы один визит на `mikameo.github.io`. ## 11. Слепые зоны и исправления сбора (сделано 2026-09-12)

1. **+21 цель** создана через Management API (реестр v3 = 56, на счётчике 60): tab_ordnance, 18 × ordnance_*, library_doc_open, library_copy_markup. Управление зависающими POST: `create_metrika_goals.py` продолжает пакет при таймауте одной цели и возвращает код 3 → повторный прогон подтверждает чтением.

3. **Дев-шум по clientID вместо дней** — см. шапку; на клиентской стороне ничего менять не нужно.
4. **События без целей восстановимы полностью** через `goal://`-хиты Logs API (раньше считалось, что только частично через params). Это снимает остроту правила «цель в том же инкременте», но не отменяет его: Reporting API и UI Метрики без цели слепы.
