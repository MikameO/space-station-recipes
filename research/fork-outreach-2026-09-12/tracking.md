# Fork outreach — схема ссылок и замера

**Зачем:** сейчас весь трафик из Discord и вики сливается в «Direct» (89% визитов окна чекпойнта-3). Чтобы понять, какое сообщество дало сколько пользователей, у каждого размещения должна быть своя ссылка. Базовая линия — Dead Space: гайд в `#📒┆гайды` с 2026-07-27 дал 133 пользователя за 47 дней (2.8 новых в день, ~40% всех запусков калькулятора), см. [../site-analytics-2026-09-12/insight-audience-acquisition.md §2](../site-analytics-2026-09-12/insight-audience-acquisition.md).

## 1. Формат ссылки

```
https://mikameo.github.io/space-station-recipes/?utm_source=<fork_id>&utm_medium=<placement>&utm_campaign=outreach-2026-09#src=<fork_id>
```

| Часть | Значения | Смысл |
|---|---|---|
| `utm_source` | `fork_id` из реестра (`misfits`, `goob`, `rucm`, …) | **кто** привёл: сообщество форка |
| `utm_medium` | `discord-guide`, `discord-pin`, `wiki`, `forum`, `steam-guide` | **где** лежит ссылка |
| `utm_campaign` | `outreach-2026-09` | волна; следующая волна получит новое значение |
| `#src=<fork_id>` | тот же `fork_id` | сайт сразу открывается с фильтром нужного форка |

Query-параметры ставятся **до** `#`. Для Dead Space уже работающая ссылка `#src=deadspace` без UTM остаётся как есть: менять живое размещение ради метки не нужно, его вклад виден по `startURL`.

Пример для Misfits в канале гайдов:

```
https://mikameo.github.io/space-station-recipes/?utm_source=misfits&utm_medium=discord-guide&utm_campaign=outreach-2026-09#src=misfits
```

Для вики того же форка:

```
https://mikameo.github.io/space-station-recipes/?utm_source=misfits&utm_medium=wiki&utm_campaign=outreach-2026-09#src=misfits
```

## 2. Почему это безопасно для приложения (проверено по коду 2026-09-12)

- `app.js:128` читает из query только `mode`; остальные параметры игнорируются, на hash-состояние (`#src=`, `#tab=`, `#r=`) не влияют.
- `index.html:85`: Метрика инициализируется с `url: location.href`, то есть UTM снимаются при загрузке, до любых `replaceState`.
- `sw.js:80-83`: service worker отдаёт `index.html` с `ignoreSearch`, любая query-строка получает закэшированную страницу и офлайн-режим не ломается.
- Share-ссылки, которые генерирует сам сайт, UTM не несут: повторные шаринги внутри сообщества будут видны как Direct, это ожидаемо.

## 3. Что и где смотреть

| Вопрос | Где в Метрике | Где в выгрузке |
|---|---|---|
| Сколько визитов/юзеров дало сообщество | Источники → Метки UTM → `utm_source` | `reports/all/utm.json` (`ym:s:UTMSource,ym:s:UTMMedium,ym:s:UTMCampaign`) |
| Какое размещение работает (канал гайдов против вики) | там же, уровень `utm_medium` | то же |
| Пользуются ли калькулятором | сегмент «UTM Source = <fork>» → цели `calc_run`, `batch_plan` | Logs API: `ym:s:lastUTMSource` + `goalsID` (`analysis/vis.py`) |
| Остались ли | сегмент → Посетители → Новые/вернувшиеся; когорты | `analysis/vis.py`, когорты по `clientID` |
| Работает ли ссылка без UTM (старые размещения) | Содержание → Страницы входа, `#src=<fork>` | `reports/*/start_url.json` |

Для чекпойнта-4 добавить в `export_metrika_stats.py` срез `utm` (сейчас он есть только в полном свипе `export_metrika_all.py`).

## 4. Критерии пилота

- Пилот: 3 сообщества (1 RU + 2 EN), 14 дней, потом сравнение с базой Dead Space, потом волна на остальные.
- Ожидание от сообщества с ≥ 40 игроков онлайн: ≥ 1 новый пользователь в день после первой недели. Меньше 10 пользователей за 14 дней — сначала проверить само размещение (ссылка не закреплена, утонула в канале, модератор не опубликовал), и только потом делать выводы о спросе.
- Удержание августовской волны было 10% в следующий месяц при 13–25% у прежних когорт. Считать успехом прирост ядра (пользователи с ≥ 5 визитами), а не пик визитов.
- Дата разбора: чекпойнт-4 ~2026-10-10, таблица «сообщество → визиты → юзеры → calc_run → вернувшиеся».

## 5. Журнал размещений

Каждое размещение записывать в [contacts.md](contacts.md), колонка «Статус»: дата, канал, кто разрешил, какая ссылка. Без журнала атрибуция по UTM не восстановит, *что именно* было размещено.
